## [0.18.0] - 2026-05-27

### Added
- **`gost-report` skill: поддержка `\begin{cases}`, `\begin{pmatrix}`, `\begin{bmatrix}` и аналогичных fenced matrix в `formula()`.** latex2mathml сериализует эти конструкции как `<mo fence>{</mo><mtable>…</mtable>[<mo fence>}</mo>]`, но прежний mtable-хендлер не видел окружающие fences — cases рендерилась как центрированная матрица без скобок, pmatrix/bmatrix теряли свои `(`/`[`. Новый `_try_fenced_mtable` распознаёт паттерн в children mrow и эмитит `<m:d>` (delimiter) с правильными `begChr`/`endChr` вокруг матрицы. Cases-стиль (открывающая `{` без парной закрывающей) автоматически выравнивается по левому краю через `<m:mcs><m:mc><m:mcPr><m:mcJc m:val="left"/>` — обе ветви прижимаются влево, как требует ГОСТ-стиль cases. Pmatrix/bmatrix остаются с дефолтным центрированием. Логика fence-detection покрывает оба формата сериализации: latex2mathml ≥3.77 для `\left\{ … \right.` ставит `stretchy="true" fence="true"`, для bracket-matrix пишет голый текстовый `(` или `[`. Скобочные множества: `( [ { | ‖ ⟨ ⌊ ⌈` для open, парные для close. Refactor: вынесен общий `_build_mtable(table_node, *, left_align)` — переиспользуется fenced- и plain-mtable хендлерами. Регрессии: fraction, sub/sup, plain `array` (без обрамляющих fences) рендерятся как раньше — `_try_fenced_mtable` возвращает None при отсутствии паттерна и обработка падает в существующий `_walk_with_nary`. End-to-end проверено: `Report(...).formula(r"f(x) = \begin{cases} x^2 & x \geq 0 \\ -x & x < 0 \end{cases}")` пишет валидный OMML с `<m:d m:begChr="{" m:endChr=""/>` и левым выравниванием колонок, файл открывается в Word/LibreOffice без warnings.
- **`ultrasearch` skill: новый флаг `--parse-concurrency N` (default 4) для параллельного парсинга PDF.** Stage 1 раньше парсил PDF серийно через subprocess — `pymupdf4llm` releases the GIL, но сам subprocess invocation был bottleneck'ом на корпусах >20 PDF (≈3 минуты wall-clock на типичный lit review из 30 статей). Новый `--parse-concurrency` (с дефолтом 4) ограничивает `asyncio.Semaphore`, который гейтит `asyncio.to_thread(_run_parse_subprocess, …)` вызовы — до N PDF парсятся параллельно, остальные ждут на семафоре. Subprocesses остаются изолированными (каждый — отдельный `python parse.py …`), так что параллельные pymupdf4llm/docling invocations не могут затереть друг другу state — safety property serial-subprocess дизайна сохраняется. Порядок результатов поддерживается через `zip(parse_jobs, results)`, поэтому `parsed[key]` мэппинг остаётся корректным. Trade-off: память растёт линейно от `--parse-concurrency` (каждый воркер грузит pymupdf4llm и опционально docling — ≈300-500 MB на воркер), `--parse-concurrency 1` возвращает прежнее серийное поведение для memory-constrained окружений. `stats["parse"]` теперь включает `concurrency` поле для аудита итераций.

### Fixed
- **`ultrasearch` skill: discovery через Semantic Scholar полностью отвалилось без API key.** S2 закрыл `/paper/search` для keyless clients где-то в 2024 — каждый вызов возвращает 429 даже с conservative backoff, и `_query_s2()` бесшумно отдавал пустой список. Источник `s2` в итоге практически выпадал из default cascade'а для пользователей без `S2_API_KEY`. Fix: переключение на `/paper/search/bulk` — этот endpoint всё ещё работает без ключа, возвращает до 1000 результатов за вызов и принимает идентичный `fields` параметр и идентичную форму response (`{"data": [...]}`), поэтому `_s2_to_candidate` mapping не трогался. Trade-off: bulk endpoint не поддерживает relevance ranking — только `paperId` / `publicationDate` / `citationCount` сорта. `citationCount:desc` выбран как лучший proxy для lit-review ранжирования (плюс — соответствует тому, как исследователи обычно скимают S2 результаты). Live verification: keyless `query=transformer` возвращает 1000 результатов, top — "Attention is All you Need", релевантность приемлемая. Параметр `limit` убран — у bulk endpoint его нет, slice до `n` теперь делается клиентом (`results[:n]`).

## [0.17.0] - 2026-05-26

### Added
- **`doc2kb` skill: opt-in MinerU VLM backend для image-only и сложных layout PDF.** Default lightweight tier doc2kb остаётся без изменений ни на байт — heavy ML deps (`mineru[all]`, MLX wheels на Apple Silicon, ~3 GB модель) никогда не активируются автоматически и не входят в обычный bootstrap. Включается строго по явному действию пользователя в двух местах: `ensure_env.py --tier mineru` (additive install поверх lightweight base, отдельный `.installed_hash_mineru` для идемпотентности) и `scout_corpus.py --enable-mineru` (без флага image_only PDF продолжают surfac'иться как user-decision группа `ask_user_ocr_strategy` со скипом по дефолту). Новый extractor `extract_pdf_mineru.py` оборачивает MinerU 2.5+ CLI (`mineru -p ... -o <tmpdir> -b auto|pipeline|vlm-auto-engine -l cyrillic`), парсит `<stem>/<resolved_backend>/<stem>_content_list.json` для page_idx-aware splice'а `[page N]` anchors в плоский markdown MinerU'я, копирует все embedded images из `images/` через существующий `save_image_safe` в `<kb_dir>/assets/<doc_id>-pageNN-imgM.<ext>` с full ReWrite Markdown/HTML image references в body, и эмиттит ту же `{ok, out, tokens_estimated, warnings, ...}` JSON-форму что и прочие extract_*.py — single-file contract сохранён. На отсутствие mineru binary — exit 2 с install-hint (`ensure_env.py --tier mineru` или manual `uv pip install -U 'mineru[all]'`), парент-цикл должен трактовать это как «нужен tier install» а не как corrupt-PDF crash. Frontmatter `extraction_method` пишется как `mineru-<resolved_backend>@<version>` — резолвед бекенд приходит из имени folder'а MinerU'я (auto → vlm или pipeline после device detection). `--keep-raw` сохраняет per-doc raw output под `<kb_dir>/_mineru/<doc_id>/` для последующего opt-in Popo. `_scout.json` получает `flags.enable_mineru` для audit trail; `estimated_extraction_seconds` теперь учитывает mineru route как ~2 s/page. Strategy `mineru` добавлен в перечень в `references/format-spec.md` и `references/extraction-recipes.md`; SKILL.md получил две новые секции — "Optional MinerU VLM backend (opt-in)" и "Optional stage 2" — с полной командной строкой для CLI, scout, прямого вызова и совмещения с Popo.
- **`doc2kb` skill: opt-in MinerU-Popo post-processor (`postprocess_popo.py`) для document-level tree reconstruction.** Опциональный stage 2 поверх mineru extractor'а — реконструирует heading hierarchy, cross-page table merging, paragraph truncation repair, image↔caption association через upstream 4B-модель MinerU-Popo. Заявленная upstream-метрика — TEDS hierarchy 53.7 → 90.6 на mineru output. doc2kb ships только glue: extract_pdf_mineru.py с `--keep-raw` кэширует raw mineru output под `<kb_dir>/_mineru/<doc_id>/`, postprocess_popo.py резолвит путь к user-provided Popo checkout (через `--popo-repo` или `DOC2KB_POPO_REPO` env), валидирует upstream layout (наличие `scripts/run_label_normalization.sh`, `scripts/run_inference.sh`, `scripts/build_tree.sh`), staging'ует кэш в `<popo>/post-process/mineru/<run_name>/<doc_id>/` (Popo's нормализатор сканит per-source subdirs), последовательно запускает 3 bash-скрипта (с опциями `--skip-normalization`/`--skip-inference` для итеративных reruns), извлекает построенное дерево из `<popo>/outputs/build_tree/mineru/<run_name>/<doc_id>/` (берётся самый большой `.json` — robust к Popo filename drift) и пишет sidecar `<kb_dir>/docs/<doc_id>-<slug>.tree.json` рядом с каждым kb doc. Body `.md` не переписывается — tree consumption оставлен агенту, который строит финальные RAG chunks. На отсутствие POPO_NOT_FOUND_HINT (env var unset / repo не найден / не Popo checkout) — exit 2 с пошаговой инструкцией клонирования + conda env + HF model download (`hf download DreamEternal/MinerU-Popo`) + редактирования `model_utils.py` для `POPO_MODEL_PATH`. Doc2kb сам по себе НЕ ставит Popo, не качает 4B модель, не дёргает Qwen/GPT API для enrichment'а — это всё пользовательская инфраструктура. Mineru cache reused как-есть, без дополнительной нормализации — Popo принимает MinerU output из коробки (упомянуто в Popo README как поддерживаемый source).
- **`doc2kb` skill: `ensure_env.py --tier <name>` для opt-in heavy install'ов поверх lightweight base.** Новый pattern: `requirements.txt` остаётся минимальным (~50 MB установки), а тяжёлые tier'ы живут отдельными файлами (`requirements-mineru.txt` — первый клиент). Tier-bootstrap (`bootstrap_tier(tier)`) гарантирует, что lightweight base установлен, затем сравнивает sha256 тирового requirements-файла с `.venv/.installed_hash_<tier>` (отдельный от base hash) — идемпотентность: `--tier mineru` это no-op если ничего не поменялось, и переключение между tier'ами не триггерит переустановку базы. flock (`.venv.lock`) удерживается на время tier-install'а — два параллельных `--tier mineru` зова безопасны. Парсинг `--tier` сделан вручную без argparse, чтобы ensure_env.py сохранил stdlib-only footprint (нужно для bootstrap'а до того как venv существует). Convenience-resolver bare script name (`extract_pdf_mineru.py` → `<scripts_dir>/extract_pdf_mineru.py`) теперь корректно работает после `--tier` flag stripping — `ensure_env.py --tier mineru extract_pdf_mineru.py args` идёт по нужному пути.

## [0.16.2] - 2026-05-26

### Fixed
- **`doc2kb` skill: pymupdf4llm dropped one letter from `fi`/`ff`/`fl` ligature glyphs, silently corrupting English PDFs.** pymupdf4llm ≤ 1.27.x reassembles spans into markdown without using the PDF's ToUnicode CMap correctly: glyphs whose CMap entry maps to a single ASCII char come through with the second letter missing — `Official`→`Ofcial`, `flexible`→`fexible`, `first`→`frst`, `traffic`→`trafc`, `sufficient`→`sufcient`, `effect`→`efect`, `affect`→`afect`, `quantifier`→`quantifer`, `Difficulty`→`Diffculty`, etc. Raw `pymupdf.Page.get_text("dict")` returns the words correctly — the bug is local to pymupdf4llm's higher-level assembler — so we patch on our side via a hardcoded prefix-match table. New `_common.recover_ligatures(text) → (text, n_replacements)` runs after `clean_whitespace` in `extract_pdf_pymupdf4llm.py` and again (idempotent) in `normalize_md.py`, so re-running normalize on already-extracted corpora heals them retroactively. The replacement preserves the first character's case (`Ofcial`→`Official`, `ofcial`→`official`), uses negative-lookbehind `(?<![A-Za-z])` instead of `\b` so it fires when a broken word is wrapped in markdown italic (`_fnd_`→`_find_`; `\b` fails there because `_` is a word character), and uses lookaheads to disambiguate prefixes that double as legit English (`dif(?=cult|er)` matches only the broken cases — `differ`/`different` survive because they have `diff`+letter, so position 3 is `f` not `e`, and the lookahead fails). Surfaces `ligatures_recovered: N word(s)` as a warning in the JSON output and `ligature_residual: ...` when an unrecognized broken pattern survives (signal to extend `_LIGATURE_FIXES`). Hardcoded list intentionally — a general `\Bfer\b → fier` rule would clobber legit `defer`/`prefer`/`refer`/`transfer`/`confer`/`infer`/`differ`/`offer`/`buffer`; a spell-checker fallback was rejected because of false positives on technical terms, proper nouns, and multilingual corpora. Tested on a real academic PDF: 9 broken words fixed in first pass, 0 in second (idempotent), 0 false-positives on the `differ`/`defer`/`prefer`/`refer`/`transfer`/`offer`/`buffer` regression list.
- **`doc2kb` skill: standalone footer page numbers leaked into normalized bodies because `detect_recurring_lines` could not see them.** Footer line `7` on page 7, `8` on page 8, etc. — each line unique, so the recurring-line detector (threshold 0.7) treats them as content. New `_common.strip_page_footer_numbers(body) → (body, n_removed)` uses positional patterns: `\n\n\d{1,4}\n+(?=\[page \d+\])` (number sandwiched between two `[page N]` anchors with only whitespace) and `\n\n\d{1,4}\n*\Z` (number at the very end, after the last page anchor). Preserves the `[page N]` anchors themselves — they're the second-session agent's navigation primitive. Wired into both `extract_pdf_pymupdf4llm.py` (logs `stripped N footer page number(s)`) and `normalize_md.py` (`footer_page_numbers: N` in the report dict).
- **`doc2kb` skill: `references/pitfalls.md` gained item 14 documenting the pymupdf4llm ligature bug with detection recipe, fix mechanism, and a "do NOT" list (no manual rewriting, no spell-checker, no unanchored regexes that destroy `defer`/`prefer`/etc.).** Existing item 14 (Unicode NFC filename normalization) renumbered to 15.

## [0.16.1] - 2026-05-24

### Fixed
- **`ultrasearch` pipeline crashed on Python 3.14 with a misleading `sentence-transformers/torch not importable: cannot import name 'GenerationMixin' from 'transformers.generation'` error.** Root cause: `scripts/profile.py` shadowed the stdlib `profile` module when `scripts/` was prepended to `sys.path` (via `ensure_env.py` writing `ultrasearch.pth` to site-packages AND setting `PYTHONPATH=scripts_dir + os.pathsep + ...` before `os.execv`). Python 3.14's `cProfile.py:23` does `run.__doc__ = _pyprofile.run.__doc__` where `_pyprofile` is `import profile` — when the stdlib `profile` was replaced by our YAML loader, the AttributeError propagated up through `torch._dynamo.convert_frame` (which imports `cProfile`) into the lazy `transformers.models.auto.auto_factory` chain that resolves `GenerationMixin`, finally surfacing inside `index.load_embedder()` as the cryptic `transformers.generation` ImportError. Fix: rename `scripts/profile.py` → `scripts/_profile.py` (matches the `_common.py` convention), update the two imports in `scripts/orchestrate.py` and `scripts/ultrasearch.py`, and adjust the docstring + JSON Schema description that referenced the old filename. Verified by running a full `--profile=academic` pipeline end-to-end (discovery → fetch → index on MPS → retrieve → traverse → synthesize) without errors. The bug was latent in 0.16.0; it manifested on any fresh install whose Python interpreter exhibits the cProfile→profile attribute lookup at module-init time (3.14 confirmed; earlier 3.x likely affected too once `torch._dynamo.aot_compile` triggers `cProfile` import).

## [0.15.1] - 2026-05-23

### Fixed
- **Skills silently dropped by Codex CLI due to over-long descriptions.** Codex enforces a hard 1024-**byte** (not character) limit on the YAML `description:` field; skills exceeding it are rejected at load time with `invalid description: exceeds maximum length of 1024 characters` and never appear in the active skill list. All three shipped skills were over: `ultrasearch` (1263 B), `doc2kb` (1064 B), `gost-report` (1027 B) — cyrillic and em-dash characters are multi-byte in UTF-8, which made byte-count diverge sharply from visible length. Compressed descriptions to 825–856 B by moving implementation details (7-tier fetch cascade, SPECTER cosine gate, pymupdf4llm+docling chain, redundant trigger phrases, university list duplication) into the SKILL body where they were already documented. Trigger keywords (RU+EN) preserved.

### Added
- **`scripts/validate-skills.py` — byte-accurate description-length validator.** Reads each `skills/*/SKILL.md`, extracts the YAML `description:` field, fails fast (exit 1) if any exceeds 1024 UTF-8 bytes. Stdlib-only (no PyYAML dependency). Refuses multi-line YAML descriptions (`|`/`>` block scalars) with exit 2 to avoid silent under-counting. Run manually or wire into CI.
- **`scripts/git-hooks/pre-commit` — repo-local commit gate.** Only fires when a `skills/*/SKILL.md` is in the staged set, so unrelated commits stay instant. Skips silently when `python3` is unavailable. Enable per-clone with `git config core.hooksPath scripts/git-hooks` (one-time setup, also activates the existing `commit-msg` attribution-stripper).
- **CLAUDE.md: description-size-limit rule + setup instructions.** Skill Format section now documents the 1024-byte hard limit and points at the validator + hook; Structure and Commands sections list both new files.

- **`gost-report` skill: invisible automatic validation.** New `skills/gost-report/scripts/validate.py` module deterministically checks the generated `.docx` against ГОСТ 7.32 rules — long/short dash leakage in body text outside auto-captions, missing or non-monotonic figure/table captions, bare LaTeX (`\frac`, `\sum`, `\sqrt`, etc.) in prose, placeholder name leaks (`Фамилия И.О.`), AI-tone phrase bank from `SKILL.md`'s writing-style block. Two delivery layers:
  - **L1 (always-on, every target).** `Report.save()` writes a `<docx>.gost-meta.json` sentinel next to the file, then runs the validator and raises `GostValidationError` on any tier-(a) violation. The model sees a Python traceback in the shell exactly as it would for any failing tool call — and the exception text is the only validation-related prose in the entire skill, visible only on failure. Tier-(b) heuristic warnings print to stderr without raising.
  - **L2 (default-on for `--target claude`, opt-out via `--no-gost-validation` / `-NoGostValidation`).** A `Stop` hook merged into `~/.claude/settings.json` runs `python validate.py --hook` on every model Stop. The script scans cwd (depth ≤ 6) for sentinel files, validates each described `.docx`, and emits `{"decision":"block","reason":"..."}` JSON on tier-(a) violations — Claude Code feeds the reason back to the model so it self-corrects on the next turn. Hook always exits 0, even on its own internal error; cannot break the Stop pipeline. Sentinel-only scoping means zero false fires in projects that don't use `gost-report`.
- **Skill body shrinks ~7.5 KB.** `SKILL.md`'s `## Checklist` section (11 lines) and `references/checklist.md` (76 lines) deleted — the validator is now the source of truth for everything that can be checked deterministically. The model's context never carries a manual checklist that could be forgotten in long generations; it thinks only about how to write the report. `grep -i 'валидаци|checklist|validate' SKILL.md` → 0 matches after this change.

### Changed
- **`Report.save()` now raises `GostValidationError(RuntimeError)` on validation failures.** Subclasses `RuntimeError` (not `Exception` directly) so existing user code with narrow `except IOError`/`except OSError` is unaffected. **BC NOTE:** code with broad `except Exception:` around `r.save()` will mask validation failures — review and let `GostValidationError` propagate, or catch specifically and re-raise after handling. The exception message explicitly tells the model not to suppress the error and not to switch to `python-docx` directly — those are the two failure modes the design defends against.
- **`validate.py` self-bootstraps via the skill venv when invoked as a CLI.** When the Stop hook fires `python validate.py --hook`, the system python likely lacks `python-docx`. The script detects this, locates `<skill_dir>/.venv/bin/python` (created by `r.save()`'s first invocation via `ensure_env.py`), and re-execs under that interpreter. Net effect: the hook command in `settings.json` stays a one-liner, and validation kicks in once the user has run the skill at least once.

### Notes
- **Codex compatibility.** Codex CLI has no hooks, so L2 is unavailable on `--target codex`. L1 (in-library raise) works identically — the model sees Python tracebacks regardless of target. The validator script ships in both targets' skill copies and remains usable in `--check <docx>` mode for manual debugging.
- **`--uninstall` does not auto-strip the Stop hook entry from `settings.json`** (same precedent as `--no-attribution-fix` / `--no-config-defaults` / `--with-sound-hooks` since v0.7.x). Re-running `bash install.sh --no-gost-validation` does not remove the previously-merged hook either; users who want to revert must edit `~/.claude/settings.json` manually.

## [0.6.2] - 2026-04-27

### Fixed
- **`gost-report`: nested N-ary operators (∑∑, ∫∑, ∑∏, …) no longer leave a placeholder square between the inner operator and its body.** v0.5.0 collected the body of an N-ary operator at the `mrow` level via lookahead, but only one level deep — the inner operator's `<m:e>` stayed empty because its body siblings were consumed at the outer level instead. Verified end-to-end on `\sum\sum`, `\sum\prod`, and the original 8-formula regression suite — 0 empty `<m:e>` left.

## [0.4.4] - 2026-04-27

### Added
- **`gost-report`: hard enforcement against em-dashes.** The soft writing-style rule from v0.4.3 was still being ignored — agents kept putting `—` into report prose. Now two layers of protection:
  1. **Prompt.** `SKILL.md` opens with a top-level "⛔ Правило №1 — приоритет выше всего остального" block right after the H1, listing exactly where em/en-dashes are forbidden (`r.text`, `r.task`, headings, list items, captions, table cells) and what to write instead (comma between words, hyphen in ranges). The old writing-style section now defers to this rule.
  2. **Code.** `gost_report.py` adds `_sanitize_prose()` — every content method (`text`, `task`, `h1/h2/h3`, `numbered`, `bullet`, table cells, and the user `caption` argument in `figure`/`table`) runs input through regexes: ` — ` / ` – ` → `, ` and bare `—`/`–` → `-`. The library-generated prefixes «Рисунок N — Описание» and «Таблица N — Описание» are untouched because the dash there is mandated by GOST and inserted by the library itself.
- The sanitizer is a safety net, not a license to relax — `SKILL.md` explicitly tells the model not to rely on it and to write without em-dashes from the start.

## [0.4.3] - 2026-04-26

### Added
- **`gost-report`: hard writing-style rule for prose.** New `## Writing style — обязательно соблюдать` section in `SKILL.md` makes the model write report body text in a natural Russian voice instead of the typical AI register: no em-dashes, no «ёлочки», no канцеляризмы («в ходе выполнения работы», «является», «данный», etc.), varied sentence rhythm. Scoped to prose only — auto-generated captions (`Рисунок N — Описание`) and canonical structural headings (`Введение`, `Заключение`) are explicitly exempt because they're library-formatted per GOST.

## [0.4.2] - 2026-04-26

### Fixed
- **`gost-report`: large screenshots no longer overflow page margins.** `figure()` now clamps the image width to the printable area (A4 width minus left+right body margins from the active profile — typically ~17 cm for ITMO, ~16.5 cm for GOST). Previously, calling `figure(path, caption)` without `width_cm` used the image's native dimensions, which for typical screenshots (1300-2500 px @ 144 DPI = 23-43 cm) extended past the right margin and into the page edge in Word. Verified end-to-end on real lab screenshots (Cisco Packet Tracer captures); images now fit cleanly. Explicitly set `width_cm` is also clamped as a safety net.
- No PIL/Pillow dependency added — image natural size is read via `docx.image.image.Image.from_file`, which python-docx already ships.
