## [Unreleased]

### Fixed
- **Codex silently skipped `doc2kb` and `ultrasearch`.** Their YAML `description:` contained `: ` (colon-space), which Codex's strict YAML loader (Ruby Psych) misparses as a mapping indicator and drops the skill — while Claude Code's lenient parser accepted it, so the breakage was Codex-only and invisible locally. Quoted both descriptions (single-quoted scalars, inner `'` doubled); valid YAML for both parsers and the parsed value is byte-identical. (cherry-picked from PR #7 by virxdxk.)

### Added
- **`validate-skills.py` now FAILs on a YAML-hostile *unquoted* skill description** (`: `, trailing `:`, or ` #` in a plain scalar) — the regression guard for the Codex fix above, so pre-commit and CI catch it before Codex does. `gost-report` (no `: `) is unaffected; quoted descriptions are exempt.

## [1.2.0] - 2026-06-07

### Added
- **`god` preset grows three more gated power-user layers, each with a `--with-*`/`--no-*` flag pair (mirrored as PowerShell switches), all skipped in non-interactive shells and "don't-intrude" when already present:**
  - `--with-gh` — install GitHub CLI (`gh`) via the system package manager (brew/apt/dnf/pacman/zypper; winget/choco/scoop on Windows) **only if it's missing**. Official GitHub tool, not `curl|bash`. Interactive y/N.
  - `--with-claude-skip` — add a `claude-skip` shell alias (zsh/bash rc; PowerShell `$PROFILE` function) for `claude --dangerously-skip-permissions`, behind a loud security warning. Deliberately **not** named `claude`, so the permission-bypass is an explicit per-invocation opt-in; never duplicates an existing alias.
  - `--with-playwright` — install Microsoft's official `@playwright/cli` (terminal browser automation with persistent + parallel sessions — what the Playwright MCP can't do) and its bundled agent skill via `npm i -g @playwright/cli@latest && playwright-cli install --skills`, **only if no playwright cli/mcp is already set up**. agentpipe installs the tool; the skill ships with it — never vendored into this repo.
- The resolved-preset manifest and `--dry` output now print the gh / claude-skip / playwright lines; installer flag parity (validate-repo Check E) preserved across `install.sh` and `install.ps1`.

### Security
- **Supply-chain hardening of the `god` preset's external installs (from a `/audit` pass).**
  - **caveman is now pinned + checksum-verified.** Replaced the moving `main` ref with a fixed commit SHA and a `sha256` that is verified before the script runs (downloads to a temp file, compares, refuses on mismatch — never `curl … | bash` of unpinned HEAD). An accepted `y` now authorizes the exact bytes the maintainer reviewed. CWE-494/CWE-829/CWE-426.
  - **Pinned `ccstatusline` and `@playwright/cli`** to exact versions (no `@latest`). The ccstatusline `statusLine` previously re-resolved `@latest` via `npx -y` on *every* session, forever — now pinned.
  - **`--uninstall` is now reversible for the dangerous god side-effects:** it strips the marker-scoped `claude-skip` alias from the shell rc / `$PROFILE`, removes the agentpipe `ccstatusline` `statusLine` (only if unmodified), and prints a "left in place" list with reversal commands for externally installed tools (caveman/gh/playwright) and merged settings keys.
  - **New `validate-repo.py` Check F (FAIL):** the build fails if `@latest` or a `main`/`master` `raw.githubusercontent.com` ref appears anywhere in `install.sh`/`install.ps1` — a machine guard against unpinned-external regressions.
  - **Documented the External-Inclusion Bar** (Tier A/B/C) in `CLAUDE.md` + `docs/installation.md`: `god` installs only agentpipe's own content (A) or pinned, reversible, official vendor tools (B); third-party-exec / safety-weakening layers (C) are banned except the two explicitly-gated, hardened entries (caveman, claude-skip).
  - claude-skip warning strengthened (recommends an OS sandbox; notes it persists until `--uninstall`).

## [1.1.0] - 2026-06-07

### Added
- **Installer presets — `--preset <name>` (`-Preset` on PowerShell): one named bundle instead of stacking a dozen toggles.** An escalating ladder `minimum < default < senior < god`, plus a `codex-full` combo for the Codex target. A preset sets per-layer **defaults**; any explicit flag overrides the preset for that layer, and `--skills-only` still wins over everything — precedence is `target < preset < explicit flags < --skills-only`. Resolution is a two-pass model: parse records which layer flags the user passed explicitly (a `*_SET` bit per flag in bash; `$PSBoundParameters` in PowerShell), then the preset fills only the layers the user left at default. A no-`--preset` install is **byte-for-byte unchanged** (the resolver is skipped entirely). The resolved manifest (every layer on/off + model profile + sound + MinerU/caveman) prints before the first write and under `--dry`, which doubles as the cure for "I don't remember what the default install does" — `--preset default --dry`.
  - **`minimum`** — tools + safety only: agents/commands/skills + launchers + config-defaults (security deny-list) + gost-report persona config. OFF: attribution-fix, CLAUDE.md baseline, gost-validation hook — nothing that mutates global git config or installs a session hook.
  - **`default`** — the no-flag baseline, named so its manifest is visible.
  - **`senior`** — `default` + Stop sound + thinking summaries + maxed non-secret env defaults merged into `settings.json` `"env"` (`CLAUDE_CODE_EFFORT_LEVEL=xhigh`, `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`).
  - **`god`** — everything `senior` gives plus ccstatusline + caveman + MinerU pre-warm, on `--model-profile opus`. Notification sound is deliberately left **off** (it duplicates the Stop beep — the one toggle dedup the maintainer called out).
  - **`codex-full`** — Codex-native bundle (implies `--target codex` unless `--target` is given): skills + gost-config + Stop sound + launchers. A Claude-oriented preset under `--target codex` now warns and recommends `codex-full` instead of silently dropping every Claude-only layer.
- **New opt-in layers, each with a `--with-*` / `--no-*` flag pair (mirrored as PowerShell switches):**
  - `--with-env-defaults` — merge the maxed perf/privacy env block into `settings.json` `"env"` (preserves existing env keys; no secrets shipped — ultrasearch's OpenAlex/Unpaywall/S2 keys stay manual). `xhigh` raises per-turn reasoning **and** quota use.
  - `--with-ccstatusline` — add a [ccstatusline](https://github.com/sirmalloc/ccstatusline) `statusLine` block (`npx -y ccstatusline@latest`), **install-if-missing** so it never clobbers an existing `statusLine`; renders only once `npx` is on PATH.
  - `--with-caveman` — install [caveman](https://github.com/JuliusBrussee/caveman) via its third-party `curl|bash` installer. **Gated:** interactive `y/N` (default N) with the URL shown, skipped in non-interactive shells, and (PowerShell) a `bash`-availability pre-flight so the user is never asked to confirm an install that can't run.
  - `--with-mineru` — pre-warm doc2kb's MinerU tier (`ensure_env.py --tier mineru`, ~3 GB). Same hard gate as caveman: interactive confirm, non-interactive skip. Upholds the project rule that heavy ML deps are never auto-installed or silently routed.
- **Installer flag parity (validate-repo Check E) preserved** — all nine new long options (`--preset`, `--with`/`--no` for mineru/env-defaults/ccstatusline/caveman) exist identically in `install.sh` and `install.ps1`. Documented in README (preset table) and docs/installation.md (Install Presets section + flag table).

## [1.0.0] - 2026-06-06

First stable release. Gated multi-agent pipeline orchestration for Claude Code and Codex CLI — 9 specialist agents, 16 workflows, and a multi-vendor skill suite, installed globally in ~30 seconds.

### Highlights

- **`gost-report` grows a plugin ecosystem.** A small core + opt-in modules you compose right in `build.py`, all sharing one continuous «Рисунок N» counter: matplotlib charts (`r.plot.*`, GOST/grayscale-safe palette), Graphviz diagrams (`r.diagram` — structural schemes, algorithm flowcharts per ГОСТ 19.701), bibliography (`r.bib`, ГОСТ Р 7.0.5), GOST cross-references (`r.ref` — «на рисунке N», not bare numbers), and inline math (`$...$` LaTeX inside any prose). The LaTeX→OMML subsystem was extracted as the reference module; new modules scaffold with `scripts/new_module.py` (design in `research/19`).
- **`doc2kb` ships a built-in retrieval layer.** Every knowledge base is self-searchable via a portable BM25 index (`query.sh` — SQLite FTS5, pure-stdlib fallback, no embeddings/API, Cyrillic + Latin), plus a one-shot `dkb` CLI for no-agent use.
- **CLI launchers `gr` / `us` / `dkb`** installed on PATH with the skills (conflict-safe), so agents and humans skip the long `ensure_env.py` invocation. `gr` auto-discovers `.claude/gost-report/build.py`.
- **Byte-deterministic `.docx`** across processes (pinned `docProps/core.xml` timestamps); GOST normocontrol fixes (comma before «где», units in table headers, references by word).

Full detail below.

### Changed
- **`gost-report`: extracted the LaTeX→OMML formula subsystem into the first vendored plugin module `gost_report_math/` — behavior-preserving, the reference example for cloning future modules.** The ~640-line OMML pipeline (constants + `_walk_mathml`/`_handle_*`/`_build_nary`/`_try_fenced_mtable`/… + `latex_to_omath`) moved verbatim from the `gost_report.py` monolith into `gost_report_math/_omml.py` (pure functions, no `Report` state); the GOST formula layout (centered formula + right-aligned «(N)» number) moved into `gost_report_math/module.py` (`MathModule` → `r.math.formula`, namespace `math`, auto-discovered via `registry._BUILTIN`). `Report.formula(...)` is now a one-line BC-shim delegating to `self.math.formula(...)` — identical signature and output. `gost_report.py` shrank **2182 → 1525 lines (−30%)**. New CoreServices facades back the module without it touching `Report` privates: `next_formula_number()`, `make_paragraph()`, `add_text_paragraph()`, `set_run_font()`, `space_block`. Math attaches lazily (latex2mathml is in the default tier but a document without formulas never imports it). **Verified byte-for-byte behavior-preserving** by a golden-master characterization harness: 86 LaTeX cases (fractions, sup/sub/subsup, roots, n-ary sum/prod/int with limits + body terminators, all 10 accents, lim/max/min, fenced brackets, pmatrix/bmatrix/cases, relations, nested) serialized to OMML XML + the full `document.xml` + a stable docx sha (excluding the volatile `docProps/core.xml` wall-clock timestamp) — all identical between the pre-extraction monolith and the extracted module; an in-process part-by-part diff confirmed every zip part matches. The harness is a throwaway (kept in `/tmp`, not committed — repo rule: validation via real usage, no test files). Removed two now-dead imports (`xml.etree.ElementTree as _ET`, `WD_TAB_ALIGNMENT`). No user-facing change; `r.formula` and existing scripts work unchanged. (Latent, pre-existing and out of scope: `docProps/core.xml` carries a wall-clock timestamp, so a `.docx` is byte-identical only within a process, not across processes — flagged for a separate fix.)
- **`gost-report`: install-template `config.env.example` now ships a loud, self-pointing ФИО/группа placeholder, and the placeholder is treated as *unset*.** The global personal config (`~/.config/gost-report/config`, installed by `install.sh`/`install.ps1` install-if-missing — already wired) previously seeded `GOST_REPORT_STUDENT_NAME="Фамилия И.О."` / `GOST_REPORT_STUDENT_GROUP="P3XXX"` — quiet placeholders a fresh user could accidentally ship on a title page. They are now `"ЗАПОЛНИ: ФИО → ~/.config/gost-report/config"` / `"ЗАПОЛНИ: группа"`, and any value containing the token `ЗАПОЛНИ` is treated as unfilled: `_apply_env_overrides` skips it (so it never overrides a real `build.py` value), and `Report._check_required` counts it as missing — so the first `r.save()` fails with a `ValueError` that names the exact config path instead of silently generating a report with the placeholder on the title page. The error message now points at the resolved `_config_file_path()` and lists all four config layers (env var → `<курс>/.gost-report.env` → global config → `TitleConfig(...)`). No change for users whose config holds real data (their values don't contain the token). SKILL.md "Персональный конфиг" documents the blocking behaviour.

### Fixed
- **`gost-report`: byte-deterministic `.docx` across processes — `docProps/core.xml` no longer embeds a wall-clock timestamp.** `_strip_python_docx_fingerprints` already neutralized the python-docx creator/description/thumbnail fingerprints, but it set `dcterms:created`/`dcterms:modified` to `datetime.now()` at save — so the *same* document built in two separate processes produced different `core.xml` bytes (every other zip part was already deterministic). Pinned both timestamps to a fixed value via a new `_deterministic_timestamp()` helper: honors `SOURCE_DATE_EPOCH` (reproducible-builds convention) when set, else the constant `2000-01-01T00:00:00Z`; `cp:revision` is pinned to `1` and `cp:lastModifiedBy` stays empty. **Verified:** building an identical document (title_page=False, one h1, body text) in two separate Python processes now yields an identical full-docx sha256 (previously only the within-process bytes matched); a per-part diff confirms `core.xml` is the *only* part affected by the timestamp setting — `document.xml` and every other part stay byte-for-byte unchanged. Discovered during the math-module extraction (commit `03dd481`) but pre-existing and out of scope there; this resolves the "flagged for a separate fix" note in that entry.
- **`gost-report`: Stop-hook no longer recursively walks the whole filesystem from a large cwd.** `validate.py --hook` (the deterministic Stop-hook installed into `~/.claude/settings.json`) scanned for `*.gost-meta.json` sentinels with `cwd.rglob(...)` — which descends the **entire** subtree and only *afterwards* filters results by `HOOK_GLOB_MAX_DEPTH`, so the depth cap never bounded the traversal. Launching Claude Code from `$HOME` or `/` made every Stop (once per turn) walk that whole tree; the install.sh "~5ms no-op" claim only held for small project dirs. Replaced with a self-contained bounded walk (`_scan_sentinels`): an explicit stack that prunes at depth and skips noisy/heavy dirs (`node_modules`, `.git`, `.venv`, `site-packages`, `Library`, …), preserving the exact prior depth semantics (`len(rel.parts) <= HOOK_GLOB_MAX_DEPTH`, verified at the boundary d=6 keep / d=7 drop). Added a cheap pre-scan gate (`_under_project_root`): the hook returns 0 immediately unless cwd or an ancestor — **excluding `$HOME` itself**, since `~/.claude` always exists — holds a project marker (`.git`/`Makefile`/`pyproject.toml`/`.claude`), so `$HOME`/`/`/loose dirs are never scanned. No behavioural change for real gost-report projects (sentinels in `<project>/docs/` at depth 1–2 still validate); the hook still always exits 0. Installer comment corrected to describe the bounded walk.

### Added
- **CLI launchers `gr` / `us` / `dkb` installed onto PATH with the skills (no opt-in).** Agents and humans now run `gr build.py`, `us "query" --max-papers 30`, `dkb in/ out/` instead of the long `python3 ~/.claude/skills/<name>/scripts/ensure_env.py …` form — short, memorable, usable by a non-technical end user. `install.sh`/`install.ps1` write thin shims to `~/.local/bin` (`$AGENTPIPE_BIN_DIR` to override; `.cmd` on Windows) that bake the installed skill path (env-overridable via `GOST_REPORT_SKILL`/`ULTRASEARCH_SKILL`/`DOC2KB_SKILL`) and exec the skill entry. **Conflict-safe:** if a same-named command already exists on PATH and isn't ours (marker-detected), it's skipped with a warning, never clobbered; a reinstall updates our own shim in place. Removed on `--uninstall`, previewed in `--dry`, opt-out with `--no-launchers`/`-NoLaunchers`. Installer flag parity (validate-repo Check E) preserved. **`gr` is smart:** `gr <path>` runs that build; `gr` with no argument walks up from the cwd to find `.claude/gost-report/build.py` (the conventional default build location) and runs it — discovery logic lives in cross-platform `gost-report/scripts/cli.py`, so the bash and `.cmd` shims stay trivial and identical. `us`/`dkb` always forward their arguments. The three skills' SKILL.md now lead with the short command (with the long `ensure_env.py` form kept as an explicit fallback for when the launcher isn't on PATH). Verified end-to-end in a sandbox HOME: shims generated with correct baked paths + env override, `gr` no-arg discovery + explicit-path + `--help` all work, conflict-skip fires on a foreign `dkb`. Documented in docs/installation.md (flag table + launchers section) and each SKILL.md.
- **`gost-report`: inline math — `$...$` LaTeX inside any prose renders as a native Word equation.** Previously math lived only in block `r.formula(...)`; running text and the `where=` explanation wrote bare characters, so `x_i` was the literal glyphs `x`, `_`, `i` rather than a real subscript. Now every prose entry point — `r.text`, `r.task`, formula `where=`, figure/table captions, list items, table cells — supports LaTeX delimited by `$...$`, rendered as inline `<m:oMath>` interleaved with text runs (true subscripts, fractions, Greek, etc.). Same LaTeX surface as `r.formula` (the OMML pipeline in `gost_report_math`, lazy-imported only when a `$` is present). The math segment is **not** run through the prose sanitizer (syntax preserved); surrounding prose still obeys the no-em-dash rule; `\$` is a literal dollar sign. New core primitive `_append_inline` + public service `add_inline_paragraph`; a `$`-guard keeps every dash-free, math-free paragraph **byte-for-byte identical** to before (verified: math golden master still matches 86/86 + document.xml, and a no-`$` document produces zero `<m:oMath>`). `r.figure()`/`r.table()` also now **return their number** (was `None`) so `r.ref.in_table(t)` works. Documented in SKILL.md ("Инлайн-математика"). Validated by a 7-check inline harness (block+inline counts, subscript rendering, escaped `\$`, comma-before-«где», no-`$` byte-stability).
- **`doc2kb`: built-in retrieval layer — every knowledge base now ships its own BM25 search engine (`index_kb.py` Phase 4.5 + `query_kb.py`).** The KB is consumed by a *second* agent; before this it navigated only by `INDEX.md` headings + `Grep`, which floods a large corpus with unranked hits and burns tokens. Phase 4.5 closes that gap with **zero new dependencies**. `index_kb.py <kb_dir>` slices every `docs/*.md` into structure-aware passages — split on `[page N]` anchors → headings → blank-line paragraphs, token-bounded (target 400 / cap 512), **overlap-free**, fenced code kept intact — and indexes them in `<kb_dir>/_index.db` via **SQLite FTS5/BM25** (tokenizer `porter unicode61 remove_diacritics 2`: English stemming + Cyrillic + diacritic folding, so a Russian corpus is as searchable as an English one). Each chunk is indexed with a **deterministic contextual header** (`Doc title › heading path › page N`) weighted 2× in `bm25()` — the no-LLM, no-hallucination slice of Anthropic's Contextual Retrieval, which lets a passage about "results" match "transformer results" even when its body never repeats the title. FTS5 presence is probed at build time and recorded in `meta.fts`; when this CPython lacks FTS5, `query_kb.py` transparently falls back to a **pure-Python BM25** over the same `chunks` table (k1=1.5, b=0.75, context counted 2×) — same ranking semantics, no extra deps. `query_kb.py <kb_dir> "<question>"` returns citation-first ranked passages (`source › heading › page N  [doc-id]  score` + highlighted snippet, `--show` for full text, `--json`, filters `--doc/--type/--page`, `--and`, `--raw`, `--info`; FTS5 `bm25()` sign handled — most-negative = most relevant, reported flipped). The script is **pure stdlib and copied verbatim into each KB as `_query.py`** with `query.sh`/`query.cmd` launchers, so the KB is self-contained and **searchable on any machine with just `python3` — no venv, no skill dir, no network**. Idempotent by corpus signature (sorted doc-id+sha256 + chunk params): re-running on an unchanged corpus is a no-op (`--force` to rebuild). **Verbatim & deterministic** — chunks are source bytes, never summarized, so the `source_sha256` provenance guarantee is untouched (doc2kb rule #1 upheld). Wired throughout: `dkb run` now auto-indexes (extract → **index** → manifest) with `--no-index` to skip, plus `dkb index` / `dkb query` subcommands; `build_manifest.py` folds a «Search (recommended first step)» section + per-doc distinctive terms into `INDEX.md` when `_index.db` is present (degrades gracefully to heading + grep otherwise); `AGENTS.md` instructs the second agent to **search first, then Read**; `update_kb.py` rebuilds the index on every live-KB refresh *if one already exists* (note-KBs stay lean — search is never forced). **Heavy-deps-opt-in invariant upheld**: the index is lightweight-tier (stdlib `sqlite3` + tiktoken for chunk sizing), never a torch/embeddings/API path. Design validated against 2025-2026 evidence (Amazon "Keyword search is all you need" AAAI 2026; Anthropic removing RAG from Claude Code; Contextual Retrieval): agentic BM25 reaches ~90 %+ of vector-RAG answer quality for a grep+Read agent at a fraction of the infra. Verified end-to-end on a mixed EN+RU corpus: FTS5 and python-fallback backends return consistent top-k rankings; contextual-header weighting surfaces the right section; portable `query.sh` runs with no venv; idempotency + `--force` + `--no-index` + live-KB refresh all confirmed. Documented in SKILL.md (Phase 4.5, "Querying the knowledge base", scripts inventory, output tree, `dkb` table) and the README skills table.
- **`gost-report`: two pure-python plugin modules — `bib` (ГОСТ Р 7.0.5 bibliography) and `ref` (cross-references) — plus normocontrol fixes from a defense review.** `gost_report_bib` (namespace `r.bib`, default tier, no deps): `r.bib.add(key, type=..., ...)` registers a source (types `book`/`article`/`web`/`conference`/`standard`/`thesis`; fields authors/title/city/publisher/year/pages/journal/volume/issue/url/accessed/doi/edition), `r.bib.cite(*keys) → "[N]"` numbers sources by **first-citation order** (vancouver-style — numbers match the rendered list), `r.bib.references()` emits the «Список использованных источников» structural element (via `h1` → TOC) with a numbered list formatted to ГОСТ Р 7.0.5. The « — » area separator is **mandatory** in that standard, so entries are rendered raw (not through the prose sanitizer) and `validate.py` now exempts them. `gost_report_xref` (namespace `r.ref`, default tier): GOST-correct reference phrasing instead of a bare number — `on_figure(n)`→«на рисунке N», `in_table(n)`→«в таблице N», `by_formula(n)`→«по формуле (N)», `per_figure/per_table`→«в соответствии с …», nominative `figure/table/formula`, parenthetical `see_figure/see_table`, all with `cap=` for sentence start and an optional label registry (`r.ref.set("arch", n)`). **Normocontrol fixes:** (1) `r.formula(..., where=...)` now emits the GOST-required **comma after the formula** before the «где» line (layout-only — OMML conversion unchanged, golden-master confirms all 86 cases identical, only `where`-cases' `document.xml` changes); (2) `validate.py` `_check_dashes` learned a section-aware bibliography exemption — em-dashes inside «N. …» entries under a «Список использованных источников / литературы» heading no longer false-fail the dash rule (enters on the heading, exits on the next structural heading). Both registered in `registry._BUILTIN` (`bib`, `ref`). Documented in SKILL.md (API table, "Список литературы и ссылки", "Правила оформления" incl. table-header units guidance: «Количество образцов»/«Доля, %» not «Образцов»/«Доля»). Validated by an assertion harness (28 checks: per-type bib formatting, cite numbering/dedup/errors, every xref phrasing + labels, formula comma, full-document validation passes).
- **`gost-report`: pluggable visual modules (`r.plot.*`, `r.diagram`) + core+modules plugin architecture.** The `Report` monolith grows a small extension seam so visuals attach as opt-in modules that all share ONE continuous «Рисунок N — …» figure counter (GOST 7.32 §6.5) — a matplotlib chart, a mermaid diagram, and a pre-made PNG increment the same sequence. New top-level `core_api.py` (Protocols `ReportModule`/`Figure`/`CoreServices` + `ActionableImportError`) and `registry.py` (two-channel discovery: explicit `_BUILTIN` for vendored modules that work in the skill folder without pip + on the Codex target, plus optional `importlib.metadata` entry points for third-party `gost-report-*` pip packages). `Report` gains lazy `__getattr__` attach (`r.plot`/`r.diagram` import nothing until first use — a report without charts never imports matplotlib), public CoreServices facades (`embed_figure`/`embed_table`/`printable_cm`/`sanitize`/`tmp_dir`/`paths`), and `figure()`/`embed_figure()` now accept a `Figure` object (renders → PNG) or a path interchangeably; tmp PNGs are cleaned in `save()`/`__del__`. **`gost_report_viz`** (tier `[viz]`: numpy+matplotlib only, ~66 MB — scipy/pandas deliberately excluded) ships `line/scatter/bar/grouped_bar/histogram`, one `apply_gost_style()` rcParams preset (serif chain Liberation Serif→Times New Roman→PT Serif→DejaVu Serif, `mathtext.fontset=stix`), the Okabe-Ito palette plus a second channel (linestyle/marker/hatch) so series read in grayscale, and byte-deterministic PNGs (`savefig(metadata={'Software':None})` + content-hash filenames — verified identical bytes across renders). **`gost_report_diagrams`** (namespace `r.diagram`) renders **Graphviz/DOT → PNG** via the system `dot` binary (`brew`/`apt install graphviz`) — no pip dependency, no Node, no rasterizer (PNG is emitted directly). It covers structural diagrams, algorithm flowcharts (ГОСТ 19.701 shapes via DOT), trees, ER, dependency graphs. GOST-clean styling is injected out of the box (light-grey rounded boxes, dark border, black text, serif font matching Times New Roman — reads in grayscale); user DOT attributes override the defaults. - **`doc2kb` skill: точечный page-patching через MinerU прямо в существующий extraction.** Когда `extract_pdf_pymupdf4llm.py` помечает PDF warning'ом `dropped_pictures: N placeholder(s) remain over M page(s)` с конкретными страницами, прежний воркфлоу был "перегнать весь PDF через mineru" (часы на 1000-страничную книгу) или "ручная транскрипция через Read tool". Новый `extract_pdf_mineru.py --pages 2,18-19,35,221,243-244 --patch-into <kb_dir>/docs/<doc>.md` берёт только перечисленные оригинальные страницы PDF, нарезает их в subset через pymupdf (внутри tempdir, никаких staging-файлов на диске пользователя), прогоняет mineru только по этому subset'у (≈10 c/страницу на vlm-mlx M-серии — 9 страниц = полторы минуты вместо часов), затем remappит `[page N]` маркеры и asset filenames из subset-индексов (1..K) обратно к оригинальным номерам PDF (`[page 243]`, `<doc_id>-page243-mineru-imgM.<ext>`) и вшивает результат в существующий target md, заменяя только `[page N]` секции из --pages — преамбула, остальные страницы и primary `extraction_method` frontmatter не трогаются. Page-список парсится через новый `_common.parse_page_list("2,18-19,35,221,243-244")` с поддержкой запятых и `start-end` диапазонов (validation: range descending / negative / zero / out-of-range → ValueError с понятным сообщением). Splice логика построена на двух helper'ах в _common — `split_body_by_page_anchors(body) → (preamble, {page_no: section})` режет существующий target по `^\[page \d+\]$` маркерам в стартах строк, `assemble_body_from_sections(preamble, sections)` собирает обратно в page-ordered порядке с парой blank lines между секциями. Дубликат asset наименования с pymupdf4llm output (тот же `<doc_id>-pageNN-imgM.<ext>` pattern) предотвращён обязательным `-mineru` infix'ом в filename — pymupdf4llm-вые `<doc_id>-page04-img1.jpx` и mineru-вые `<doc_id>-page004-mineru-img1.jpeg` живут рядом в `<kb_dir>/assets/` и никогда не пересекаются. Padding для mineru-asset страниц всегда `:03d` (стабильный независимо от subset size — патч pages=[28] и потом pages=[28, 142] оба эмиттят `page028`, иначе один день `page28`, другой `page028`, и target md ломается). Frontmatter target после splice'а: `mineru_patched_pages: [4, 5, 28]` (sorted union с предыдущими патч-запусками — accumulated across calls), `extraction_method_supplementary: mineru-<backend>@<version>` (alongside, не replaces primary), `extraction_date` обновляется к сегодня, `tokens_estimated` пересчитывается с merged body, `assets` union с deduplicated preserve-first-seen ordering, `warnings` accumulates single splice-summary entry ("mineru_patch: replaced N page section(s) [...] via mineru-<backend>@<version>") плюс mineru-side warnings под префиксом `mineru_patch[…]:`. Safety: refuses splice если target's `source_sha256` ≠ input PDF sha256 (exit 1 с хинтом `--force-patch` для известных re-export'ов того же документа); refuses если `--patch-into` задан без `--pages` (full-document replace тривиально destructive); все page номера validated против doc.page_count перед mineru subprocess invocation (`requested pages out of range for <file> (1..N): [200, …]`). `--pages` без `--patch-into` — standalone patches mode: пишет полноценный md в `<output_md>` со всеми frontmatter полями + `mineru_subset_pages: [2, 18, 19, ...]`, page anchors / asset filenames уже remappped к оригинальным, ready к ручному review перед splice'ом. Backward compat: без `--pages` поведение скрипта identical к старому — `subset_to_original=None`, asset suffix empty (`<doc_id>-pageNN-imgM.<ext>` 2-digit), no новых frontmatter полей. Stdout JSON success теперь несёт `patched_pages`/`patched_into`/`extraction_method_supplementary` extras в splice-mode и `mineru_subset_pages` в standalone-subset mode. SKILL.md "Что делать, если warning всё-таки появился" секция переписана: mineru page-patch теперь recommended вариант (с командной строкой и расценками), Read-tool transcription оставлен fallback для случаев когда tier не установлен или VLM не справляется. `references/extraction-recipes.md` получил отдельную "Page-targeted patching with mineru" секцию с пошаговым разбором что делает скрипт; `format-spec.md` документирует три новых frontmatter поля (`mineru_subset_pages`, `mineru_patched_pages`, `extraction_method_supplementary`). Тестовое покрытие: 10 end-to-end сценариев на реальной 183-страничной книге (Введение в Windows Server 2016) — standalone subset extraction, splice mode in-place, fail-fast на --patch-into без --pages, page out of range, malformed page syntax, sha256 mismatch без --force-patch, asset suffix collision-avoidance, 3-digit padding для pages > 99, cumulative patches с union frontmatter, стабильный padding для повторных запусков.

## [0.18.0] - 2026-05-27

### Added
- **`gost-report` skill: поддержка `\begin{cases}`, `\begin{pmatrix}`, `\begin{bmatrix}` и аналогичных fenced matrix в `formula()`.** latex2mathml сериализует эти конструкции как `<mo fence>{</mo><mtable>…</mtable>[<mo fence>}</mo>]`, но прежний mtable-хендлер не видел окружающие fences — cases рендерилась как центрированная матрица без скобок, pmatrix/bmatrix теряли свои `(`/`[`. Cases-стиль (открывающая `{` без парной закрывающей) автоматически выравнивается по левому краю через `<m:mcs><m:mc><m:mcPr><m:mcJc m:val="left"/>` — обе ветви прижимаются влево, как требует ГОСТ-стиль cases. Pmatrix/bmatrix остаются с дефолтным центрированием. Логика fence-detection покрывает оба формата сериализации: latex2mathml ≥3.77 для `\left\{ … \right.` ставит `stretchy="true" fence="true"`, для bracket-matrix пишет голый текстовый `(` или `[`. Скобочные множества: `( [ { | ‖ ⟨ ⌊ ⌈` для open, парные для close. Refactor: вынесен общий `_build_mtable(table_node, *, left_align)` — переиспользуется fenced- и plain-mtable хендлерами. Регрессии: fraction, sub/sup, plain `array` (без обрамляющих fences) рендерятся как раньше — `_try_fenced_mtable` возвращает None при отсутствии паттерна и обработка падает в существующий `_walk_with_nary`. End-to-end проверено: `Report(...).formula(r"f(x) = \begin{cases} x^2 & x \geq 0 \\ -x & x < 0 \end{cases}")` пишет валидный OMML с `<m:d m:begChr="{" m:endChr=""/>` и левым выравниванием колонок, файл открывается в Word/LibreOffice без warnings.
- **`ultrasearch` skill: новый флаг `--parse-concurrency N` (default 4) для параллельного парсинга PDF.** Stage 1 раньше парсил PDF серийно через subprocess — `pymupdf4llm` releases the GIL, но сам subprocess invocation был bottleneck'ом на корпусах >20 PDF (≈3 минуты wall-clock на типичный lit review из 30 статей). Новый `--parse-concurrency` (с дефолтом 4) ограничивает `asyncio.Semaphore`, который гейтит `asyncio.to_thread(_run_parse_subprocess, …)` вызовы — до N PDF парсятся параллельно, остальные ждут на семафоре. Subprocesses остаются изолированными (каждый — отдельный `python parse.py …`), так что параллельные pymupdf4llm/docling invocations не могут затереть друг другу state — safety property serial-subprocess дизайна сохраняется. Порядок результатов поддерживается через `zip(parse_jobs, results)`, поэтому `parsed[key]` мэппинг остаётся корректным. Trade-off: память растёт линейно от `--parse-concurrency` (каждый воркер грузит pymupdf4llm и опционально docling — ≈300-500 MB на воркер), `--parse-concurrency 1` возвращает прежнее серийное поведение для memory-constrained окружений. `stats["parse"]` теперь включает `concurrency` поле для аудита итераций.

## [0.16.2] - 2026-05-26

### Fixed
- **`doc2kb` skill: pymupdf4llm dropped one letter from `fi`/`ff`/`fl` ligature glyphs, silently corrupting English PDFs.** pymupdf4llm ≤ 1.27.x reassembles spans into markdown without using the PDF's ToUnicode CMap correctly: glyphs whose CMap entry maps to a single ASCII char come through with the second letter missing — `Official`→`Ofcial`, `flexible`→`fexible`, `first`→`frst`, `traffic`→`trafc`, `sufficient`→`sufcient`, `effect`→`efect`, `affect`→`afect`, `quantifier`→`quantifer`, `Difficulty`→`Diffculty`, etc. Raw `pymupdf.Page.get_text("dict")` returns the words correctly — the bug is local to pymupdf4llm's higher-level assembler — so we patch on our side via a hardcoded prefix-match table. New `_common.recover_ligatures(text) → (text, n_replacements)` runs after `clean_whitespace` in `extract_pdf_pymupdf4llm.py` and again (idempotent) in `normalize_md.py`, so re-running normalize on already-extracted corpora heals them retroactively. The replacement preserves the first character's case (`Ofcial`→`Official`, `ofcial`→`official`), uses negative-lookbehind `(?<![A-Za-z])` instead of `\b` so it fires when a broken word is wrapped in markdown italic (`_fnd_`→`_find_`; `\b` fails there because `_` is a word character), and uses lookaheads to disambiguate prefixes that double as legit English (`dif(?=cult|er)` matches only the broken cases — `differ`/`different` survive because they have `diff`+letter, so position 3 is `f` not `e`, and the lookahead fails). Surfaces `ligatures_recovered: N word(s)` as a warning in the JSON output and `ligature_residual: ...` when an unrecognized broken pattern survives (signal to extend `_LIGATURE_FIXES`). Hardcoded list intentionally — a general `\Bfer\b → fier` rule would clobber legit `defer`/`prefer`/`refer`/`transfer`/`confer`/`infer`/`differ`/`offer`/`buffer`; a spell-checker fallback was rejected because of false positives on technical terms, proper nouns, and multilingual corpora. Tested on a real academic PDF: 9 broken words fixed in first pass, 0 in second (idempotent), 0 false-positives on the `differ`/`defer`/`prefer`/`refer`/`transfer`/`offer`/`buffer` regression list.
- **`doc2kb` skill: standalone footer page numbers leaked into normalized bodies because `detect_recurring_lines` could not see them.** Footer line `7` on page 7, `8` on page 8, etc. — each line unique, so the recurring-line detector (threshold 0.7) treats them as content. New `_common.strip_page_footer_numbers(body) → (body, n_removed)` uses positional patterns: `\n\n\d{1,4}\n+(?=\[page \d+\])` (number sandwiched between two `[page N]` anchors with only whitespace) and `\n\n\d{1,4}\n*\Z` (number at the very end, after the last page anchor). Preserves the `[page N]` anchors themselves — they're the second-session agent's navigation primitive. Wired into both `extract_pdf_pymupdf4llm.py` (logs `stripped N footer page number(s)`) and `normalize_md.py` (`footer_page_numbers: N` in the report dict).
- **`doc2kb` skill: `references/pitfalls.md` gained item 14 documenting the pymupdf4llm ligature bug with detection recipe, fix mechanism, and a "do NOT" list (no manual rewriting, no spell-checker, no unanchored regexes that destroy `defer`/`prefer`/etc.).** Existing item 14 (Unicode NFC filename normalization) renumbered to 15.

Healthy PDF с обычными формулами (не позиционно-набранными) heuristic не false-positive'ит — проверено на 5-страничной `Преобразование математических моделей динамической системы.pdf` (0 warnings). Заодно расширил heading detection с `# ...` (h1-only) на `# ` + `## ` — `pymupdf4llm` чаще эмитит главные заголовки как `##`, и манифест ранее видел `headings: []` на документах с реальной структурой.
- **`doc2kb` skill: Cyrillic/accented filenames на macOS получали ложный `extraction missing` в `manifest.json`.** macOS HFS+/APFS экспонирует filename в Unicode NFD (decomposed: `й` = `и` + ` ̆`), а `_yaml_quote` записывает frontmatter `source:` в NFC — на глаз идентично, побайтово различается. `merge_scout` сравнивал строки через равенство и для каждой записи с не-ASCII именем добавлял в `skipped[]` запись `extraction missing (no kb file, no scout skip)`, хотя `docs/<id>-*.md` лежал рядом. Фикс трёхуровневый: `_common.nfc()` (новая функция), `validate_source_rel()` нормализует в NFC, `scout_corpus.scan_file()` пишет `source_path` сразу NFC (плюс в `walk_corpus` escape-branch и в `main()` scout-failed branch), и в `build_manifest.merge_scout()` оба сайта (индекс scout-файлов и `doc_sources` set) сравниваются через `_nfc()` как defensive belt — чтобы старые `_scout.json` от прошлых запусков всё ещё давали чистый manifest. Новый item 14 в pitfalls описывает invariant.
- **`gost-report` skill: растягивающиеся скобки в формулах с `\begin{cases}` и `\left( ... \right)`.** `r.formula(...)` для кусочно-заданных функций раньше рисовал крошечную `{` рядом с двухстрочной матрицей вместо высокой скобки на всю высоту cases-блока. Причина: `latex2mathml` выдаёт `<mrow><mo stretchy="true" fence="true" form="prefix">{</mo><mtable>…</mtable></mrow>`, а наш OMML-walker отдавал `<mo>` как обычный run без обёртки в делимитер — Word рендерил скобку нерастяжимо. Теперь walker детектирует пару `stretchy=true / fence=true` `<mo>` и оборачивает содержимое в `<m:d>` с правильными `begChr`/`endChr`; для одностороннего открытого fence (cases) `endChr` пустой — Word его скрывает. Парный `\left( ... \right)` тоже выигрывает: вокруг крупного содержимого (дробей, сумм) скобки теперь стянутся под высоту тела.

## [0.11.0] - 2026-05-03

### Added
- **`gost-report` skill: invisible automatic validation.** New `skills/gost-report/scripts/validate.py` module deterministically checks the generated `.docx` against ГОСТ 7.32 rules — long/short dash leakage in body text outside auto-captions, missing or non-monotonic figure/table captions, bare LaTeX (`\frac`, `\sum`, `\sqrt`, etc.) in prose, placeholder name leaks (`Фамилия И.О.`), AI-tone phrase bank from `SKILL.md`'s writing-style block. Two delivery layers:
  - **L1 (always-on, every target).** `Report.save()` writes a `<docx>.gost-meta.json` sentinel next to the file, then runs the validator and raises `GostValidationError` on any tier-(a) violation. The model sees a Python traceback in the shell exactly as it would for any failing tool call — and the exception text is the only validation-related prose in the entire skill, visible only on failure. Tier-(b) heuristic warnings print to stderr without raising.
  - **L2 (default-on for `--target claude`, opt-out via `--no-gost-validation` / `-NoGostValidation`).** A `Stop` hook merged into `~/.claude/settings.json` runs `python validate.py --hook` on every model Stop. The script scans cwd (depth ≤ 6) for sentinel files, validates each described `.docx`, and emits `{"decision":"block","reason":"..."}` JSON on tier-(a) violations — Claude Code feeds the reason back to the model so it self-corrects on the next turn. Hook always exits 0, even on its own internal error; cannot break the Stop pipeline. Sentinel-only scoping means zero false fires in projects that don't use `gost-report`.
- **Skill body shrinks ~7.5 KB.** `SKILL.md`'s `## Checklist` section (11 lines) and `references/checklist.md` (76 lines) deleted — the validator is now the source of truth for everything that can be checked deterministically. The model's context never carries a manual checklist that could be forgotten in long generations; it thinks only about how to write the report. `grep -i 'валидаци|checklist|validate' SKILL.md` → 0 matches after this change.

### Changed
- **`Report.save()` now raises `GostValidationError(RuntimeError)` on validation failures.** Subclasses `RuntimeError` (not `Exception` directly) so existing user code with narrow `except IOError`/`except OSError` is unaffected. **BC NOTE:** code with broad `except Exception:` around `r.save()` will mask validation failures — review and let `GostValidationError` propagate, or catch specifically and re-raise after handling. The exception message explicitly tells the model not to suppress the error and not to switch to `python-docx` directly — those are the two failure modes the design defends against.
- **`validate.py` self-bootstraps via the skill venv when invoked as a CLI.** When the Stop hook fires `python validate.py --hook`, the system python likely lacks `python-docx`. The script detects this, locates `<skill_dir>/.venv/bin/python` (created by `r.save()`'s first invocation via `ensure_env.py`), and re-execs under that interpreter. Net effect: the hook command in `settings.json` stays a one-liner, and validation kicks in once the user has run the skill at least once.

### Notes
- **Codex compatibility.** Codex CLI has no hooks, so L2 is unavailable on `--target codex`. L1 (in-library raise) works identically — the model sees Python tracebacks regardless of target. The validator script ships in both targets' skill copies and remains usable in `--check <docx>` mode for manual debugging.
- **`--uninstall` does not auto-strip the Stop hook entry from `settings.json`** (same precedent as `--no-attribution-fix` / `--no-config-defaults` / `--with-sound-hooks` since v0.7.x). Re-running `bash install.sh --no-gost-validation` does not remove the previously-merged hook either; users who want to revert must edit `~/.claude/settings.json` manually.

## [0.6.2] - 2026-04-27

### Fixed
- **`gost-report`: nested N-ary operators (∑∑, ∫∑, ∑∏, …) no longer leave a placeholder square between the inner operator and its body.** v0.5.0 collected the body of an N-ary operator at the `mrow` level via lookahead, but only one level deep — the inner operator's `<m:e>` stayed empty because its body siblings were consumed at the outer level instead. Refactored the lookahead into a recursive walker (`_walk_with_nary`) that, when it encounters a nested N-ary inside an outer N-ary's body, recurses to collect the inner one's body first. Result: `J = \sum_{c=1}^{k} \sum_{x \in C_c} \|x - \mu_c\|^2` now produces a properly nested `<m:nary><m:e><m:nary><m:e>‖x−μ_c‖²` structure instead of two siblings with the norm-squared dangling outside. Verified end-to-end on `\sum\sum`, `\sum\prod`, and the original 8-formula regression suite — 0 empty `<m:e>` left.

## [0.5.0] - 2026-04-27

### Added
- **`gost-report`: native LaTeX equations.** New API method `r.formula(latex, where=None) → int` inserts a LaTeX formula as a real Word equation (OMML), not a rendered image — the formula opens editable in Word, scales cleanly, and looks native. Supports the full `latex2mathml` subset: powers/subscripts, `\frac`, `\sqrt[n]`, Greek letters, `\sum/\int/\prod` with limits, `\bar/\hat/\vec/\tilde/\dot` accents, `pmatrix/bmatrix/vmatrix`, `\text{...}`, fenced groups. Auto-numbered «(N)» pinned to the right edge per GOST 7.32, optional `where=...` block for variable explanations renders below the formula. Returns the formula's number so prose can reference it: `f1 = r.formula(...)` → `r.text(f"По формуле ({f1}) ...")`. The LaTeX string itself bypasses `_sanitize_prose` (so `\text{1—5}` doesn't get mangled); `where` text is sanitized as normal user prose.
- **`gost-report`: isolated Python environment.** New `scripts/ensure_env.py` bootstrap manages the skill's deps in a dedicated venv at `<skill_dir>/.venv/` — fixed location, single per installation, never global. Manager preference: `uv` → `conda --prefix` → stdlib `python -m venv`. Idempotent: hashes `requirements.txt` and skips work when nothing changed (millisecond no-op on warm runs). When the skill ships a new `requirements.txt`, deps auto-update on next invocation. Two modes: `python ensure_env.py` (prints venv python path) and `python ensure_env.py <script>` (bootstraps then `os.execv`s the script with venv python). Cross-platform (POSIX + Windows), stdlib only, with best-effort flock to prevent concurrent-bootstrap races.
- **`gost-report`: `scripts/requirements.txt`** — `python-docx>=1.1.0`, `latex2mathml>=3.77.0`. Single source of truth for both pip and the bootstrap.

### Changed
- **`gost-report` SKILL.md** — `## Dependencies` rewritten: agents are now told to **never** `pip install` globally, always go through `ensure_env.py`. New `### Формулы (LaTeX)` section with examples and supported subset. New `### Запуск через ensure_env.py` block under `## How to use` documenting the bootstrap workflow. Checklist gains two items (formulas render as equations, single venv per skill).
- **Installers** (`install.sh`, `install.ps1`) and **build script** (`scripts/build-skills.sh`) — strip `.venv/` and `.venv.lock` on copy/zip in both directions (install + pull). Prevents a developer's local venv from leaking into system installations or release archives, where the absolute paths in `pyvenv.cfg` would be wrong anyway.

## [0.4.4] - 2026-04-27

### Added
- **`gost-report`: hard enforcement against em-dashes.** The soft writing-style rule from v0.4.3 was still being ignored — agents kept putting `—` into report prose. Now two layers of protection:
  1. **Prompt.** `SKILL.md` opens with a top-level "⛔ Правило №1 — приоритет выше всего остального" block right after the H1, listing exactly where em/en-dashes are forbidden (`r.text`, `r.task`, headings, list items, captions, table cells) and what to write instead (comma between words, hyphen in ranges).
