# Opt-in heavy tier — VLM-grade PDF parsing via opendatalab/MinerU.
#
# Install with:
#     python3 <skill_dir>/scripts/ensure_env.py --tier mineru
#
# Default doc2kb bootstrap does NOT read this file. Adding `mineru[all]` to
# the lightweight tier would pull torch + transformers + ~3 GB of CV models
# into every `ensure_env.py` run, which we explicitly do not want.
#
# Apple Silicon notes:
#   - `mlx-vlm` is the package mineru's auto-engine selector probes for to
#     decide between mlx-engine and the much slower transformers fallback
#     (see mineru/utils/engine_utils.py::_select_mac_engine). Pin it
#     explicitly so we don't silently regress when mineru drops it from
#     its transitive deps.
#   - `mlx` + `mlx-lm` are needed by mineru_vl_utils.mlx_compat for actual
#     inference and by the LLM-aided title hierarchy feature (when used).
#   - `sys_platform == "darwin"` markers keep Linux/Windows installs from
#     trying to pull MLX wheels that aren't published for them; mineru on
#     those platforms uses CUDA or pure-CPU pipeline backends instead.
mineru[all]>=2.5,<4.0
mlx-vlm; sys_platform == "darwin"
# Pin mlx below 0.32 — version 0.31.2 introduced a regression where the
# mlx-engine throws "RuntimeError: There is no Stream(gpu, N) in current
# thread" inside multi-threaded inference; confirmed safe range is the
# 0.31.x line up to but not including 0.32. See MinerU discussion #4842.
mlx>=0.31,<0.32; sys_platform == "darwin"
mlx-lm; sys_platform == "darwin"
