# Структура контента по типу работы

Шаблоны вызовов API под типичные виды российских студенческих работ. Все примеры подразумевают, что `r = Report(TitleConfig(...), profile=...)` уже создан.

## Лабораторная работа

```python
r.toc()
r.h1("Введение")
r.text("Цель работы освоить ...")     # 1-3 абзаца, без длинных тире
r.h1("Выполнение работы")
r.h2("Задание 1")
r.task("Задание 1. Сформулируй задачу.")
r.code("команда или код")
r.text("Результат показывает ...")
r.figure("screenshot.png", "Скриншот результата")
# h2 + task + code + text [+ figure] на каждое задание
r.h1("Заключение")
r.numbered([
    "Команда X освоена.",
    "Опции Y и Z изучены.",
])
```

## ВКР / выпускная квалификационная работа

Сначала стиль вуза (`references/profiles.md`): поля, тире, списки, таблицы, список источников и титул у вузов разные. Если положения вуза нет среди встроенных стилей — сделай стиль файлом по его методичке.

```python
r = Report(TitleConfig(topic="...", student_name="...", year="2027", ...),
           profile="mbi")              # или свой стиль
```

Структура (порядок — по положению вуза, обычно так):
```python
r.h1("Реферат", toc=False)             # вне оглавления
r.volume_line()                        # «… содержит N с., N рис., N табл., N источников, N прил.»
r.keywords(["...", "...", "...", "...", "..."])   # 5–15
r.text("Объект исследования – ...")    # тире — если стиль его требует (МБИ)
r.toc()

r.h1("Введение")
r.text("Актуальность ...", lead="Актуальность.")
r.text("Задачи работы:")
r.numbered(["изучить ...;", "разработать ...;", "оценить ...."])

r.h1("1 Анализ предметной области")    # номер «1» без точки (ГОСТ 7.32 / МБИ)
r.h2("1.1 Характеристика объекта")
r.text(f"Показатели приведены {r.ref.in_table('tbl:kpi')}.")   # ссылка до таблицы
r.table(rows, caption="Показатели процесса", label="tbl:kpi", widths=[2, 10, 4])
r.h2("Выводы по главе 1")

r.h1("2 Проектирование")
...
r.h1("Заключение")
r.text("...")
r.bib.references()                     # источники в порядке первого cite()
r.appendix("Форма отчёта", "обязательное")
```

Длинный текст удобнее держать в Markdown: `r.include("vkr.md")` (SKILL.md, «Текст работы в Markdown»), источники — `r.bib.load("sources.toml")`.

## Курсовая работа / курсовой проект

То же, что ВКР, но обычно короче (1-2 главы), `teacher_label="Руководитель"`, и без отдельных подразделов «объект/предмет», если кафедра не требует.

## Отчёт по практике

```python
TitleConfig(work_type="Отчёт по практике", ...)
```

Типичная структура:
```python
r.toc()
r.h1("Введение")
r.text("Период практики ...")
r.text("Место прохождения практики ...")
r.text("Цель практики ...")

r.h1("Описание организации")
r.text("Краткое описание компании / отдела / задач, выполняемых командой.")

r.h1("Выполненные работы")
r.h2("Задача 1. ...")
r.text("Что делал, какие технологии использовал, что получилось.")
r.h2("Задача 2. ...")
r.text("...")

r.h1("Заключение")
r.text("Подведение итогов, чему научился.")
```

## Домашнее задание / РГР

Самый простой случай — обычно как лабораторная без раздела «Введение»:
```python
r.toc()
r.h1("Условие задачи")
r.text("...")
r.h1("Решение")
r.formula(r"...")  # если есть формулы
r.text("...")
r.h1("Ответ")
r.text("...")
```

## Общие принципы

- **Введение и Заключение** — обязательные для любой работы (кроме коротких ДЗ).
- **Список литературы** — обязателен для ВКР/курсовых/больших отчётов.
- **«Введение», «Заключение», «Список литературы»** — это канонические заголовки, не выдумывай альтернативы.
- **Главы в ВКР** — как требует положение вуза: по ГОСТ 7.32 и у МБИ «1 Название» (номер без точки, h1 прописными), у части вузов «Глава 1. ...». Автономер — `heading_numbering` стиля.
- **Задания в лабе** — пиши «Задание 1. ...», «Задание 2. ...» через `r.task(...)`.
- **Каждый `r.numbered(...)` стартует нумерацию заново** — если нужен один длинный список, передавай все элементы одним вызовом.
