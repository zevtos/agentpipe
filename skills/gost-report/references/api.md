# Расширенный API + поведенческие заметки

В SKILL.md есть короткая таблица методов. Здесь — детали, которые не нужны при каждой генерации, но всплывают на edge cases.

## TitleConfig — содержимое титульного листа

```
TitleConfig(
    # --- Обязательные по смыслу (env может заполнить) ---
    work_type: str = "",         # «Лабораторная работа», «Курсовая работа», «ВКР»
    topic: str = "",             # тема, БЕЗ кавычек (ГОСТ запрещает кавычки вокруг темы)
    student_name: str = "",      # «Фамилия И.О.»
    student_group: str = "",     # «P3XXX», «20.Б10-мм»
    year: str = "",              # «2026»

    # --- Команда (взаимоисключающе со student_name на титуле) ---
    student_names: list[str] = [],   # ["Иванов И.И.", "Петров П.П."]
    student_label: str = "",         # пусто = авто "Выполнили"/"Выполнил"

    # --- Опциональные ---
    work_number: str = "",     # «№1», «№3»
    discipline: str = "",      # «Системное администрирование» → строка
                               # «по дисциплине «…»» под видом работы
    variant: str = "",         # для лаб с вариантами
    teacher_name: str = "",    # «Фамилия И.О.»
    teacher_label: str = "Проверил",   # для ВКР/курсовых: "Руководитель"
    teacher_degree: str = "",          # «к.т.н.», «д.ф.-м.н.»
    teacher_position: str = "",        # «доцент», «профессор»

    # --- Переопределение полей профиля ---
    city: str = "",
    ministry: str = "",
    university_full: str = "",
    university_short: str = "",
    faculty: str = "",
)
```

Все поля опциональны на уровне dataclass, но Report при создании проверяет: `work_type`, `topic`, `student_name`-или-`student_names`, `student_group`, `year` обязаны быть заданы (в TitleConfig, в env или в `~/.config/gost-report/config`). Иначе — `ValueError` с указанием, чего не хватает и какой env-ключ это закроет. **Эта проверка пропускается при `Report(title_page=False)`** (см. ниже) — без титульника обязательные поля не нужны, `TitleConfig` можно вовсе не передавать.

Поля университета (`city`, `ministry`, `university_full`, `university_short`, `faculty`) **по умолчанию пустые** и наследуют значения из активного `UniversityProfile`. Заполнять в `TitleConfig` стоит только если на конкретном документе нужно отличие от профиля.

### Env-ключи

Все строковые поля выше доступны как `GOST_REPORT_<UPPER_NAME>` (например, `GOST_REPORT_STUDENT_NAME`, `GOST_REPORT_TEACHER_LABEL`). Команда — `GOST_REPORT_STUDENT_NAMES` (CSV).

Три слоя env, каждый перекрывает предыдущий:

1. `os.environ` — реальные переменные окружения
2. `<курс>/.gost-report.env` — subject-конфиг (поиск вверх от build.py до project root)
3. `~/.config/gost-report/config` — глобальный (`$XDG_CONFIG_HOME/gost-report/config` если задан, либо `$GOST_REPORT_CONFIG`)

Затем результат накладывается на аргументы `TitleConfig(...)`: env побеждает build.py если непустое. Подробнее см. SKILL.md, разделы «Персональный конфиг» и «Subject-уровневый конфиг».

## Поведенческие заметки

### TOC это поле Word + auto-update флаг

`r.toc()` вставляет настоящее поле Word (FIELD `TOC \\o "1-3" \\h \\z \\u`), не статический текст. Сразу после открытия файла оно пустое (placeholder).

Заодно `r.toc()` ставит `<w:updateFields w:val="true"/>` в `settings.xml`: Word, Pages и LibreOffice при первом открытии файла показывают диалог «Update fields?» — один клик «Yes» обновляет TOC + нумерацию страниц. Ручное ПКМ → «Обновить поле» больше не требуется.

**Скажи это пользователю в ответе** — он должен знать что диалог надо подтвердить, иначе оглавление останется placeholder'ом.

### Report(title_page=False) — документ без титульника

`Report(title_page=False)` собирает документ без титульного листа: одна секция сразу с полями основного текста (не с полями титульника), нумерация страниц видна с первой страницы, обязательные поля `TitleConfig` не проверяются (`TitleConfig` можно не передавать). `r.toc()`, `r.h1()` и все content-методы работают как обычно; `_just_broke_page` выставлен, так что первый h1 не делает лишний разрыв. Авто-валидация на `r.save()` титульник не требует — документ без него проходит проверку.

Env-эквивалент: `GOST_REPORT_NO_TITLE_PAGE=1` (truthy: `1/true/yes/on/да`). Env только **отключает** титул и перебивает дефолт `title_page=True`; чтобы вернуть титульник, убери переменную. Это сделано чтобы CI/скрипты могли гасить титул, не редактируя `build.py`.

### Типографика и PDF

`Report(..., typography=False, allow_dashes=False)`, `r.subtitle(text)`, `r.export_pdf(path=None, *, check=True)`. Подробно в `references/typography.md`. Без флагов проза обрабатывается как раньше: `**` и `*` в `r.text` остаются литералами. `export_pdf` работает только после `r.save()`.

### Первый h1 не делает двойной разрыв

После `r.toc()` (который сам вызывает `page_break()`) и после титульной страницы первый `r.h1(...)` не вставляет лишний разрыв. Логика управляется флагом `_just_broke_page` внутри. Не пытайся добавлять `r.page_break()` руками перед первым h1.

Остальные h1 при `h1_new_page=True` получают свойство «с новой страницы» (`page_break_before`) на самом абзаце заголовка, а не отдельный абзац с разрывом перед ним: такой абзац при заполненной до конца странице переезжает на следующую и оставляет пустую страницу.

`r.page_break()` (и разрыв в конце `r.toc()`) в готовом файле тоже становится этим свойством на следующем блоке: `r.save()` убирает абзац с разрывом и ставит `page_break_before` абзацу после него, у таблицы в первом абзаце первой ячейки. Два `page_break()` подряд дают пустую страницу. Разрыв, после которого в документе ничего нет, остаётся абзацем с разрывом.

### Списки рестартуют с 1

Каждый `r.numbered(...)` начинает новый нумерованный список с пункта 1 — независимо от предыдущих. То же для `r.bullet(...)`. Чтобы продолжить один список, передавай все пункты одним вызовом:

```python
# Неправильно — два списка, каждый начинается с 1:
r.numbered(["Шаг 1"])
r.text("Промежуточный текст.")
r.numbered(["Шаг 2"])  # тоже стартует с 1

# Правильно — один список:
r.numbered(["Шаг 1", "Шаг 2"])
```

### Без кавычек вокруг темы

ГОСТ 7.32 запрещает кавычки вокруг темы работы. Библиотека передаёт `topic` как есть — сам не оборачивай:

```python
# Неправильно:
TitleConfig(topic='«Численные методы»', ...)
TitleConfig(topic='"Численные методы"', ...)

# Правильно:
TitleConfig(topic='Численные методы', ...)
```

### Шрифты и поля не трогать вручную

Не настраивай размеры шрифта / поля страницы / межстрочный интервал через `r.doc` (raw python-docx). Если нужны другие параметры, собери `UniversityProfile` (см. `references/profiles.md`). Драйвер `r.doc` это аварийный выход для совсем экзотических случаев типа альбомной ориентации страницы.

### Placeholder-имена в примерах

В качестве имён студента/преподавателя всегда пиши «Фамилия И.О.», а не реальные. Пользователь сам подставит свои. Это про:
- `student_name`
- `teacher_name`

### Авто-подписи рисунков и таблиц

Префиксы «Рисунок N — ...» и «Таблица N — ...» формирует код. Тире в этих префиксах — обязательное по ГОСТ, библиотека его ставит сама; знак, слова «Рисунок»/«Таблица», выравнивание и кегль — из стиля (`dash`, `figure_label`, `table_label`, `caption_*`): у МБИ «Таблица 1 – …». **Твой `caption` в эти префиксы попадает уже после санитайзера**: длинные тире в нём становятся запятыми. То есть когда ты пишешь `r.figure(path, "Схема сети")`, в документ попадает «Рисунок 3 — Схема сети» — это правильно, тире здесь от библиотеки, не от тебя.

### Картинки кламяются по ширине

`r.figure(image_path, caption, width_cm=None)` всегда ограничивает ширину картинки печатной областью (A4 минус поля профиля). Если `width_cm=None` — используется натуральный размер картинки, но клампится. Если `width_cm` задан — он уважается, но тоже клампится. Это защита от вылета крупных скриншотов за поля.

### Санитайзер прозы — страховка, не разрешение

`_sanitize_prose` автоматически чистит длинные/средние тире в любом пользовательском тексте. **Не полагайся на него**: текст без тире «с нуля» читается естественнее. Санитайзер исправляет твою ошибку, но факт ошибки сохраняется в виде менее естественной фразы.

Поведение санитайзера (`prose_dashes = "strip"`, стили ИТМО и ГОСТ):
- ` — ` / ` – ` (между словами) → `, `
- одиночные `—`/`–` (например в диапазонах `1—5`) → `-`

Стиль с `prose_dashes = "normalize"` (МБИ) вместо этого приводит тире к знаку стиля: « - », « — » между словами → « – », «45—60» → «45–60», дефис в словах и между цифрами («ГОСТ 7.32-2017») не трогает. `keep` — проза как есть.

Покрытие (где санитайзер прогоняется автоматически):
- Проза: `r.text`, `r.task`, `r.h1/h2/h3`, `r.numbered`, `r.bullet`.
- `caption` у `r.figure`/`r.table` (через `embed_figure`).
- **Ячейки таблиц** (`r.table(rows, ...)`) — каждая ячейка заголовка и данных санируется отдельно на момент записи, не только сквозь общий inline-проход.
- **Текст графиков `r.plot.*`** — легенда (`labels=`), подписи осей (`xlabel`/`ylabel`), `label` опорных линий (`hlines`/`vlines`) и `text` аннотаций. Этот текст запекается в PNG в обход docx-валидатора, поэтому санируется в `_VizAPI` ДО рендера (см. секцию `r.plot.*` ниже).

Что **не** санируется:
- LaTeX-строка в `r.formula(latex, ...)` (иначе сломался бы синтаксис).
- Канонические префиксы рисунков/таблиц (там тире обязательно по ГОСТ).
- Заголовки структурных элементов вроде «Введение», «Заключение».
- Числовые данные графика, `value_fmt`, цвета/стили/маркеры — не текст для чтения.

**Валидатор тоже ловит тире в ячейках.** `_check_dashes` (TIER_FAIL) обходит не только `doc.paragraphs`, но и `doc.tables` → строки → ячейки. Запрещённое `[—–]`, дошедшее до ячейки docx, жёстко падает с локацией «таблица N, строка R, столбец C» — бэкстоп на случай, если какой-то sink забыл санировать.

### Dropdown в raw python-docx

Если совсем-совсем нужно что-то нестандартное (альбомная ориентация одной страницы, кастомная нумерация подзаголовков, специальный колонтитул), доступ к нижнему уровню — через `r.doc` (это `docx.Document`). Используй экономно — большинство задач решаются через профиль или через комбинацию существующих методов.

## Подключаемые модули (графики, диаграммы)

Визуальные возможности сверх готовых PNG — это **opt-in модули** с тяжёлыми зависимостями. Подробный обзор и примеры — в SKILL.md («Графики и диаграммы»). Здесь — поведенческие заметки.

- **Активация тиром:** `GOST_REPORT_EXTRAS=viz` (или `viz,diagrams`) перед `ensure_env.py`. Без тира `r.plot`/`r.diagram` бросают `ImportError` с точной командой починки. Lightweight-дефолт matplotlib не тянет.
- **Lazy-attach:** `r.plot`/`r.diagram` ничего не импортируют до первого обращения (`Report.__getattr__` подключает модуль по требованию). Документ без графиков не платит за matplotlib.
- **Единый счётчик рисунков:** график, диаграмма и `r.figure(path, ...)` делят ОДНУ сквозную нумерацию «Рисунок N». Любой визуал-метод либо встраивает (если передан `caption=...`) и возвращает номер, либо возвращает `Figure`-объект для ручного `r.figure(fig, caption)`.
- **`r.figure(image, caption)`** теперь принимает путь ИЛИ `Figure` (chart/diagram) — один call-site для всего.
- **Детерминизм:** PNG графиков байт-стабильны (`savefig(metadata={'Software':None})`, имя по хэшу содержимого) при фиксированных версиях matplotlib/freetype. Диаграммы — best-effort (random SVG id, метрики шрифта).
- **Палитра:** Okabe-Ito + второй канал (linestyle/marker для линий, hatch для столбцов) → график читается в Ч/Б. Заголовок внутри графика не ставится (его роль — ГОСТ-подпись).
- **Диаграммы:** движок Graphviz (системный `dot`, без pip/Node, PNG напрямую). DOT-исходник; ГОСТ-оформление (серые скруглённые блоки, serif) инжектится из коробки, атрибуты в DOT его переопределяют. Опции `engine=`/`font=`/`rankdir=`. Покрывает структурные схемы, блок-схемы алгоритмов (ГОСТ 19.701), деревья, ER, графы зависимостей.
- **Новый модуль:** `python3 scripts/new_module.py <namespace> [--visual]`. Архитектура и контракты — `research/19_gost_report_module_architecture.md`, `scripts/core_api.py`.

## `r.plot.*` — общие параметры и новые методы

Все хелперы `r.plot` детерминированы: имя PNG = sha256 содержимого графика
(включая ВСЕ перечисленные ниже параметры). Любой новый видимый параметр свёрнут
в хэш, иначе два разных графика схлопнулись бы в один файл. Параметры
keyword-only, дефолты воспроизводят прежнюю картинку байт-в-байт.

**Санитайз текста графика.** Видимые человеку строки (`labels=`, `xlabel`,
`ylabel`, `label` у `hlines`/`vlines`, `text` у `annotations`) прогоняются через
санитайзер ДО сборки графика — так же, как проза. Они запекаются в PNG и обходят
docx-валидатор, поэтому чистятся здесь, у источника. Санитайз идёт до сворачивания
в контент-хэш, так что канонической (санированной) строкой определяется и имя PNG
— детерминизм сохранён: на тексте без тире хэш байт-в-байт прежний, а dashed-label
схлопывается в тот же файл, что и его уже-чистый эквивалент. Числовые данные,
`value_fmt`, цвета/стили/маркеры/`ha`/`va` не трогаются.

### Кросс-режущие kw (на line/scatter/bar/grouped_bar/stacked_bar/area/histogram)

- **`hlines`, `vlines`** — опорные линии. Список из числа ИЛИ dict
  `{value: float (обяз.), label?: str, color?: str, linestyle?: str ('-'|'--'|'-.'|':'), linewidth?: float}`.
  Рисуются в базовом `render()` после данных, перед легендой; помеченные `label`
  попадают в легенду автоматически. Дефолт линии — серый пунктир `#444444 '--'`,
  читается как вспомогательная и в Ч/Б. **Важно:** на категориальной оси
  (bar/grouped_bar/stacked_bar) `vlines` принимает числовую позицию оси
  (0-based индекс категории), а не имя категории.
- **`ylim`, `xlim`** — кортежи `(lo, hi)`; `None` = автоскейл (как раньше).
- **`yscale`** — `'linear'` (дефолт) или `'log'`. Невалидное значение → `ValueError`
  сразу (без тихого фолбэка). `'log'` с неположительными данными ругнётся в самом
  matplotlib — это ответственность вызывающего.
- **`annotations`** — текстовые выноски в координатах данных. Список dict
  `{x: float, y: float, text: str, dx?: float=6, dy?: float=6 (смещение в пунктах),
  arrow?: bool=False, color?: str, ha?: str, va?: str}`. В легенду не попадают.

### Параметры столбчатых (bar / grouped_bar / stacked_bar)

- **`value_labels: bool = False`** — печатать значение над столбцом (для
  `horizontal=True` — у конца; для stacked — по центру сегмента). Формат:
  `value_fmt.format(v)` если задан `value_fmt` (напр. `'{:.1f}'`, `'{:.0%}'`),
  иначе авто: целые как int, дробные до 3 значащих цифр без хвостовых нулей.
- **`value_fmt: str | None`** — явная строка формата.
- **`colors: Sequence[str] | None`** — явные цвета по сериям/категориям (цикл, если
  короче). `None` = детерминированная палитра Okabe-Ito (хэши прежних графиков
  стабильны).
- **`horizontal: bool = False`** (bar/grouped_bar) — `ax.barh` вместо `ax.bar`.

### Escape hatch стиля (line / scatter)

- `line`: `colors`, `linestyles`, `markers` (Sequence[str] | False — `False`
  выключает маркеры целиком, для плотных данных).
- `scatter`: `colors`, `markers`.

Все escape-hatch'и детерминированы (явные строки идут в хэш). Они переопределяют
CVD-safe дефолты — низкоконтрастные пользовательские цвета могут сломать Ч/Б-
различимость; валидации яркости нет (доверие вызывающему).

### Новые методы-формы

- **`r.plot.stacked_bar(categories, series, *, labels=None, value_labels=False, value_fmt=None, colors=None, + общие kw)`**
  — накопительные столбцы (второй канал: цвет + hatch), посерийная легенда.
- **`r.plot.area(x, y, *, labels=None, stacked=False, colors=None, + общие kw)`**
  — заливка `fill_between` (с hatch/alpha для Ч/Б); `stacked=True` → `ax.stackplot`.

### Готовые рецепты (copy-paste, минимальный отчёт)

Полный скелет отчёта с графиком — от импорта до `r.save()`. С `caption=...`
график встраивается сразу и возвращает номер; передавать путь в `r.figure` не нужно.

**Сгруппированный бар с опорной линией SLA + подписями значений:**

```python
from gost_report import Report, TitleConfig

r = Report(TitleConfig(
    work_type="Лабораторная работа",
    work_number="№4",
    topic="Анализ доступности сервиса",
))
r.h1("Результаты")
r.plot.grouped_bar(
    ["Q1", "Q2", "Q3"], [[95, 97, 99], [88, 91, 94]],
    labels=["Сервис A", "Сервис B"],
    value_labels=True, value_fmt="{:.0f}", ylabel="Доступность, %",
    hlines=[{"value": 98, "label": "SLA"}],       # серый пунктир + запись в легенде
    caption="Доступность по кварталам",
)
r.text(f"Сервис A держит SLA весь период {r.ref.on_figure(1)}.")
r.save("availability.docx")
```

**Стресс-линия с порогом SLA (hline) и моментом отказа (vline):**

```python
from gost_report import Report, TitleConfig

r = Report(TitleConfig(
    work_type="Лабораторная работа",
    work_number="№4",
    topic="Нагрузочное тестирование",
))
r.h1("Переходный процесс")
t = list(range(0, 11))                         # секунды
latency = [40, 42, 45, 51, 70, 130, 210, 260, 180, 90, 55]   # мс
r.plot.line(
    t, latency, xlabel="t, с", ylabel="Задержка, мс",
    hlines=[{"value": 200, "label": "SLA, 200 мс"}],   # порог
    vlines=[{"value": 5, "label": "пик нагрузки"}],    # момент отказа
    annotations=[{"x": 7, "y": 260, "text": "перегрузка", "arrow": True}],
    caption="Деградация задержки под нагрузкой",
)
r.save("stress.docx")
```

Заметка по детерминизму: сворачивание общих полей в базовый хэш-ключ меняет имя
PNG у ВСЕХ графиков один раз (даже при дефолтных значениях), т.к. прежний
content-key их не включал. Это безвредно — файлы content-addressed, ни один doc/тест
не ссылается на конкретный `viz_<hash>.png`; embed-конвейер берёт путь из `render()`.

## Возможности для положений других вузов

Всё ниже включается стилем (`references/profiles.md`) или аргументами методов; с дефолтами ИТМО/ГОСТ документ собирается байт-в-байт как раньше.

### Report(...)

```
Report(title=None, profile=None, *, title_page=True, project_root=None,
       typography=False, allow_dashes=False, use_env=True)
```

- `profile` — `UniversityProfile`, имя стиля («mbi»), путь к .toml/.json; `None` — `GOST_REPORT_PROFILE` из env и `.gost-report.env`, иначе ИТМО. Опечатка в значении поля — `ValueError` при создании.
- `use_env=False` — `TitleConfig` как есть: env, `.gost-report.env` и `~/.config/gost-report/config` не перекрывают его, `GOST_REPORT_NO_TITLE_PAGE` не действует. Для работы за другого человека вместо записи в `os.environ` из build.py.
- `load_profile(spec, **поля)` — стиль с полями поверх: `load_profile("mbi", numbering="chapter")`.

### Заголовки

`r.h1/h2/h3(text, *, numbered=None, toc=True)`. При `heading_numbering` стиль сам ставит «1», «1.1», «1.1.1»; структурные элементы (`unnumbered_headings`) и заголовки, уже начинающиеся с номера, номер не получают; `numbered=False/True` — вручную. `toc=False` — заголовок оформлен как h1, но не попадает в оглавление (стиль «Heading 1 Unlisted», уровень структуры «основной текст»): реферат и аннотация перед содержанием. Два заголовка подряд: интервал между ними один (у второго «до» обнуляется), если стиль задал `heading_space_before_*`.

`r.toc()` после реферата сам начинается с новой страницы (если `h1_new_page`).

### Текст и списки

- `r.text(text, *, bold, italic, markup=None, lead=None, indent=True, align=None)`: `lead="Тема."` — жирное начало абзаца; `markup=True` — `**жирный**` и `*курсив*` без режима typography.
- `r.numbered(items, nested="bullet")`, `r.bullet(items, nested="numbered")`, `r.lettered(items, nested="numbered")`. Пункт — строка или `("текст", [вложенные пункты])`. Вид вложенного списка — `nested`. Маркеры и раскладка — стиль (`list_layout`, `bullet_char`, `numbered_format`, `lettered_format`, `list_letters`). Если стиль их не меняет и вложенности нет — прежний путь через стили Word «List Number/Bullet». «а)», «б)» пишутся текстом, а не нумерацией Word: в Word нет алфавита без ё, з, й, о, ч, ъ, ы, ь.
- `r.note(text | [тексты], label=None)`, `r.example(...)`: «Примечание – Текст» с абзацного отступа; несколько — «Примечания:» и «1. Текст».
- `r.blank(n)` — пустые строки. `r.subtitle(text, *, italic, bold, line_spacing, space_after)` — дефолты из `subtitle_*` стиля.

### Таблицы

`r.table(rows, caption="", *, has_header=True, widths=None, align=None, header_align=None, font_size=None, repeat_header=None, cant_split=None, keep_together=None, note=None, continuation=None, label=None)`.

- `widths` — см по столбцам; сумма больше печатной ширины ужимается пропорционально; раскладка фиксированная.
- `align` — `"center"` для всех или по столбцам: `["left", "c", "r"]` (`l/c/r/j`); `header_align` — шапки.
- `note` — строка или список: последняя объединённая строка внутри рамки («Примечание – …» / «Примечания:»), над нижней линией, как требует ГОСТ.
- `repeat_header` (tblHeader), `cant_split` (cantSplit), `keep_together` (keepNext по строкам), `continuation` — `None` берёт значение стиля `table_*`.

### Рисунки, формулы, метки

- `r.figure(image, caption, *, width_cm=None, explication=None, label=None)`: `explication` — пояснения между рисунком и подписью.
- `r.formula(latex, *, where=None, label=None)`: `where` — строка или список пар `[(символ, пояснение), …]`: «где m – масса, кг;» с абзацного отступа (`formula_where_indent`), следующие символы под первым, `;` в конце строк и `.` в последней ставятся сами. Интервал до и после — `formula_space_pt`.
- Нумерация: `numbering = "chapter"` — «Рисунок 1.2», «Таблица 2.1», «(1.3)»; в приложении «А.1». Методы возвращают `int` при сквозной нумерации и `RefNumber` (подкласс `str`, «1.2») иначе — `r.ref.*` и f-строки печатают оба.
- Метки: `label="fig:scheme"` у `figure/table/formula/appendix` (или `r.set_label`). `r.ref.on_figure("fig:scheme")`, `r.ref.in_table("tbl:x")` работают и **до** самого элемента — положения требуют упоминать таблицу до неё: в тексте остаётся заглушка, `r.save()` ставит номер; неизвестная метка — `ValueError`. `r.ref.in_appendix("А")`, `r.ref.per_appendix("А")` — «в приложении А», «в соответствии с приложением А».

### Реферат и приложения

- `r.keywords(words)` — прописными, через запятые, без абзацного отступа, без переносов, без точки; стиль абзаца `Keywords`; вне `keywords_min…keywords_max` — предупреждение.
- `r.volume_line(template=None, **числа)` — строка объёма по `volume_template`. Рисунки, таблицы, источники `r.bib`, приложения считаются в `r.save()`; `{pages}` — поле Word NUMPAGES, его результат считает проход вёрстки. `pages=58` и т. п. — свои числа.
- `r.appendix(title, status="обязательное", *, letter=None, label=None) → буква`: с новой страницы, по центру «ПРИЛОЖЕНИЕ А», «(обязательное)», заголовок с прописной; в оглавлении одной записью. Дальше нумерация «А.1», кегль `appendix_font_size`, пока не встретится h1.

### Список источников по ГОСТ Р 7.0.100–2018

`bib_style = "7.0.100-2018"`: инициалы через пробел, город полностью («М.» → «Москва»), область «Текст : непосредственный» / «Текст : электронный» в конце (у статьи — перед «//»), 1–3 автора — первый в заголовке, 4 — все после « / », 5 и больше — три и «[и др.]», диапазоны страниц с «–». Поля сверх 7.1: `isbn`, `series`, `notes` (список: «Библиогр.: с. 37–44»), `access_mode`, `content`, `heading` («Российская Федерация. Законы.»), `number` (обозначение стандарта), `places` (`[(город, издательство), …]`), `date` (газета), `site`/`host`/`journal` + `host_subtitle`, `editors` («под ред. …»). Типы: `book`, `article`, `conference`, `web`, `standard`, `law`, `thesis`, `disk`. `subtitle` и `responsibility` — строка или список.

`r.bib.load("sources.toml")` — источники файлом (таблица на ключ, поля как у `add`; JSON тоже). `r.bib.count` — число источников (для строки объёма).

### Markdown

`r.markdown(text, base_dir=None)`, `r.include(path)` — синтаксис в SKILL.md («Текст работы в Markdown») и в docstring `scripts/markdown_input.py`. Абзацы идут через `r.text(markup=True)`, заголовки, списки, таблицы, рисунки, формулы, примечания — через те же методы, так что стиль, нумерация и проверки одинаковы с Python-вызовами. Пары «где $m$ – …; $V$ – …» превращаются в список: каждый символ с новой строки.

### Проход вёрстки (LibreOffice)

.docx не знает, где кончается страница. Если в документе есть таблицы с `continuation` или `r.volume_line()` с `{pages}`, `r.save()` конвертирует копию в PDF тем же LibreOffice, что и `r.export_pdf()`, и смотрит страницы через `pdftotext`: таблица режется перед первой строкой новой страницы, над второй частью — «Продолжение таблицы N» с новой страницы, шапка повторяется, у первой части нет нижней линии; строки таких таблиц не делятся между страницами. Проход повторяется, пока таблицы не перестанут рваться. Word считает страницы чуть иначе, поэтому разрыв ставится явно. Без LibreOffice или poppler — предупреждение, шапка всё равно повторяется, NUMPAGES Word обновит при открытии. `r.save(layout=False)` — без прохода, `layout=True` — ошибка, если LibreOffice нет. Оглавление на этом проходе — заглушка поля: если настоящее оглавление длиннее страницы, сдвиг учитывается только после обновления полей.

### Валидатор по стилю

`r.save()` пишет правила стиля в sentinel (`<docx>.gost-meta.json` → `style`): знак тире и режим `prose_dashes`, слова подписей, текст продолжения таблицы, шрифт кода, `checks`, границы ключевых слов и источников. `validate_docx(path, style=None)` и Stop-хук берут их оттуда; номера «1.2» и «А.1» проверяются по главам и приложениям, часть таблицы после «Продолжение таблицы N» не считается новой таблицей, логотип на титуле — не рисунок. Чужой .docx: `python3 scripts/validate.py --check file.docx --profile mbi`.
