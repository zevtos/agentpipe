# Расширенный API + поведенческие заметки

В SKILL.md есть короткая таблица методов. Здесь — детали, которые не нужны при каждой генерации, но всплывают на edge cases.

## TitleConfig — содержимое титульного листа

```
TitleConfig(
    # --- Обязательные по смыслу (env может заполнить) ---
    work_type: str = "",         # «Лабораторная работа», «Курсовая работа», «ВКР»
    topic: str = "",             # тема, БЕЗ кавычек (ГОСТ запрещает кавычки вокруг темы)
    student_name: str = "",      # «Фамилия И.О.»
    student_group: str = "",     # «P3XXX», «20.Б10-мм»
    year: str = "",              # «2026»

    # --- Команда (взаимоисключающе со student_name на титуле) ---
    student_names: list[str] = [],   # ["Иванов И.И.", "Петров П.П."]
    student_label: str = "",         # пусто = авто "Выполнили"/"Выполнил"

    # --- Опциональные ---
    work_number: str = "",     # «№1», «№3»
    variant: str = "",         # для лаб с вариантами
    teacher_name: str = "",    # «Фамилия И.О.»
    teacher_label: str = "Проверил",   # для ВКР/курсовых: "Руководитель"
    teacher_degree: str = "",          # «к.т.н.», «д.ф.-м.н.»
    teacher_position: str = "",        # «доцент», «профессор»

    # --- Переопределение полей профиля ---
    city: str = "",
    ministry: str = "",
    university_full: str = "",
    university_short: str = "",
    faculty: str = "",
)
```

Все поля опциональны на уровне dataclass, но Report при создании проверяет: `work_type`, `topic`, `student_name`-или-`student_names`, `student_group`, `year` обязаны быть заданы (в TitleConfig, в env или в `~/.config/gost-report/config`). Иначе — `ValueError` с указанием, чего не хватает и какой env-ключ это закроет. **Эта проверка пропускается при `Report(title_page=False)`** (см. ниже) — без титульника обязательные поля не нужны, `TitleConfig` можно вовсе не передавать.

Поля университета (`city`, `ministry`, `university_full`, `university_short`, `faculty`) **по умолчанию пустые** и наследуют значения из активного `UniversityProfile`. Заполнять в `TitleConfig` стоит только если на конкретном документе нужно отличие от профиля.

### Env-ключи

Все строковые поля выше доступны как `GOST_REPORT_<UPPER_NAME>` (например, `GOST_REPORT_STUDENT_NAME`, `GOST_REPORT_TEACHER_LABEL`). Команда — `GOST_REPORT_STUDENT_NAMES` (CSV).

Три слоя env, каждый перекрывает предыдущий:

1. `os.environ` — реальные переменные окружения
2. `<курс>/.gost-report.env` — subject-конфиг (поиск вверх от build.py до project root)
3. `~/.config/gost-report/config` — глобальный (`$XDG_CONFIG_HOME/gost-report/config` если задан, либо `$GOST_REPORT_CONFIG`)

Затем результат накладывается на аргументы `TitleConfig(...)`: env побеждает build.py если непустое. Подробнее см. SKILL.md, разделы «Персональный конфиг» и «Subject-уровневый конфиг».

## Поведенческие заметки

### TOC это поле Word + auto-update флаг

`r.toc()` вставляет настоящее поле Word (FIELD `TOC \\o "1-3" \\h \\z \\u`), не статический текст. Сразу после открытия файла оно пустое (placeholder).

Заодно `r.toc()` ставит `<w:updateFields w:val="true"/>` в `settings.xml`: Word, Pages и LibreOffice при первом открытии файла показывают диалог «Update fields?» — один клик «Yes» обновляет TOC + нумерацию страниц. Ручное ПКМ → «Обновить поле» больше не требуется.

**Скажи это пользователю в ответе** — он должен знать что диалог надо подтвердить, иначе оглавление останется placeholder'ом.

### Report(title_page=False) — документ без титульника

`Report(title_page=False)` собирает документ без титульного листа: одна секция сразу с полями основного текста (не с полями титульника), нумерация страниц видна с первой страницы, обязательные поля `TitleConfig` не проверяются (`TitleConfig` можно не передавать). `r.toc()`, `r.h1()` и все content-методы работают как обычно; `_just_broke_page` выставлен, так что первый h1 не делает лишний разрыв. Авто-валидация на `r.save()` титульник не требует — документ без него проходит проверку.

Env-эквивалент: `GOST_REPORT_NO_TITLE_PAGE=1` (truthy: `1/true/yes/on/да`). Env только **отключает** титул и перебивает дефолт `title_page=True`; чтобы вернуть титульник, убери переменную. Это сделано чтобы CI/скрипты могли гасить титул, не редактируя `build.py`.

### Первый h1 не делает двойной разрыв

После `r.toc()` (который сам вызывает `page_break()`) и после титульной страницы первый `r.h1(...)` не вставляет лишний разрыв. Логика управляется флагом `_just_broke_page` внутри. Не пытайся добавлять `r.page_break()` руками перед первым h1.

### Списки рестартуют с 1

Каждый `r.numbered(...)` начинает новый нумерованный список с пункта 1 — независимо от предыдущих. То же для `r.bullet(...)`. Чтобы продолжить один список, передавай все пункты одним вызовом:

```python
# Неправильно — два списка, каждый начинается с 1:
r.numbered(["Шаг 1"])
r.text("Промежуточный текст.")
r.numbered(["Шаг 2"])  # тоже стартует с 1

# Правильно — один список:
r.numbered(["Шаг 1", "Шаг 2"])
```

### Без кавычек вокруг темы

ГОСТ 7.32 запрещает кавычки вокруг темы работы. Библиотека передаёт `topic` как есть — сам не оборачивай:

```python
# Неправильно:
TitleConfig(topic='«Численные методы»', ...)
TitleConfig(topic='"Численные методы"', ...)

# Правильно:
TitleConfig(topic='Численные методы', ...)
```

### Шрифты и поля не трогать вручную

Не настраивай размеры шрифта / поля страницы / межстрочный интервал через `r.doc` (raw python-docx). Если нужны другие параметры, собери `UniversityProfile` (см. `references/profiles.md`). Драйвер `r.doc` это аварийный выход для совсем экзотических случаев типа альбомной ориентации страницы.

### Placeholder-имена в примерах

В качестве имён студента/преподавателя всегда пиши «Фамилия И.О.», а не реальные. Пользователь сам подставит свои. Это про:
- `student_name`
- `teacher_name`

### Авто-подписи рисунков и таблиц

Префиксы «Рисунок N — ...» и «Таблица N — ...» формирует код. Тире в этих префиксах — обязательное по ГОСТ, библиотека его ставит сама. **Твой `caption` в эти префиксы попадает уже после санитайзера**: длинные тире в нём становятся запятыми. То есть когда ты пишешь `r.figure(path, "Схема сети")`, в документ попадает «Рисунок 3 — Схема сети» — это правильно, тире здесь от библиотеки, не от тебя.

### Картинки кламяются по ширине

`r.figure(image_path, caption, width_cm=None)` всегда ограничивает ширину картинки печатной областью (A4 минус поля профиля). Если `width_cm=None` — используется натуральный размер картинки, но клампится. Если `width_cm` задан — он уважается, но тоже клампится. Это защита от вылета крупных скриншотов за поля.

### Санитайзер прозы — страховка, не разрешение

`_sanitize_prose` автоматически чистит длинные/средние тире в любом пользовательском тексте. **Не полагайся на него**: текст без тире «с нуля» читается естественнее. Санитайзер исправляет твою ошибку, но факт ошибки сохраняется в виде менее естественной фразы.

Поведение санитайзера:
- ` — ` / ` – ` (между словами) → `, `
- одиночные `—`/`–` (например в диапазонах `1—5`) → `-`

Что **не** санируется:
- LaTeX-строка в `r.formula(latex, ...)` (иначе сломался бы синтаксис).
- Канонические префиксы рисунков/таблиц (там тире обязательно по ГОСТ).
- Заголовки структурных элементов вроде «Введение», «Заключение».

### Dropdown в raw python-docx

Если совсем-совсем нужно что-то нестандартное (альбомная ориентация одной страницы, кастомная нумерация подзаголовков, специальный колонтитул), доступ к нижнему уровню — через `r.doc` (это `docx.Document`). Используй экономно — большинство задач решаются через профиль или через комбинацию существующих методов.

## Подключаемые модули (графики, диаграммы)

Визуальные возможности сверх готовых PNG — это **opt-in модули** с тяжёлыми зависимостями. Подробный обзор и примеры — в SKILL.md («Графики и диаграммы»). Здесь — поведенческие заметки.

- **Активация тиром:** `GOST_REPORT_EXTRAS=viz` (или `viz,diagrams`) перед `ensure_env.py`. Без тира `r.plot`/`r.diagram` бросают `ImportError` с точной командой починки. Lightweight-дефолт matplotlib не тянет.
- **Lazy-attach:** `r.plot`/`r.diagram` ничего не импортируют до первого обращения (`Report.__getattr__` подключает модуль по требованию). Документ без графиков не платит за matplotlib.
- **Единый счётчик рисунков:** график, диаграмма и `r.figure(path, ...)` делят ОДНУ сквозную нумерацию «Рисунок N». Любой визуал-метод либо встраивает (если передан `caption=...`) и возвращает номер, либо возвращает `Figure`-объект для ручного `r.figure(fig, caption)`.
- **`r.figure(image, caption)`** теперь принимает путь ИЛИ `Figure` (chart/diagram) — один call-site для всего.
- **Детерминизм:** PNG графиков байт-стабильны (`savefig(metadata={'Software':None})`, имя по хэшу содержимого) при фиксированных версиях matplotlib/freetype. Диаграммы — best-effort (random SVG id, метрики шрифта).
- **Палитра:** Okabe-Ito + второй канал (linestyle/marker для линий, hatch для столбцов) → график читается в Ч/Б. Заголовок внутри графика не ставится (его роль — ГОСТ-подпись).
- **Диаграммы:** движок Graphviz (системный `dot`, без pip/Node, PNG напрямую). DOT-исходник; ГОСТ-оформление (серые скруглённые блоки, serif) инжектится из коробки, атрибуты в DOT его переопределяют. Опции `engine=`/`font=`/`rankdir=`. Покрывает структурные схемы, блок-схемы алгоритмов (ГОСТ 19.701), деревья, ER, графы зависимостей.
- **Новый модуль:** `python3 scripts/new_module.py <namespace> [--visual]`. Архитектура и контракты — `research/19_gost_report_module_architecture.md`, `scripts/core_api.py`.
